# 体验证据缺口复核（2026-11-07）

## 触发

上一轮诊断：文档完备度已超过多数团队，但体验证据为零。PRD 里的 30 秒闭环、90% 选中、55fps、20cm 漂移、真实感评分，全部是推断。

## 判定

当前状态是"计划打磨"，不是"打磨"。核心问题不是文档不够，而是**没有给假设安排被证伪的机会**。

## 修正项

### PRD v0.3

| 位置 | 修正 |
|---|---|
| §1 | 增加"证据声明"：体验类数字在真机记录前都是假设，不是承诺 |
| §3.1 | 目标表增加"证据等级"列（事实 / 推断 / 假设） |
| §11.2 | 在 M0 之前插入 P0 体验原型门禁：未跑完 P0 不开始工程化 |
| §11.3 | DoD 增加：体验类 P0 必须附真机记录 |
| §11.4 | 新增体验验收：TTFS、放弃率、次日自愿再用、疲劳、真实感、出戏次数 |
| §12 | 风险表新增"文档完备掩盖体验未验证" |
| §13 | 里程碑表增加 P0 行 |

### ROADMAP

- 北极星下增加原则："先证明体验，再工程化"。
- O1 增加 KR1：P0 完成 10 次真机记录，三项指标有基线。
- §3 阶段表增加 P0 行与失败止损。
- 依赖图增加 000，001 改为依赖 000。

- §7 增加每周体验评审：录屏 + 指标 + 一条最烦的事，不看 ticket 完成率。
- §9 下一步改为 000 开工。

### Tickets

- 新增 `000 体验原型 P0`（一颗行星闭环，允许一次性代码）。
- `001` 的 `blocked_by` 改为 `[000]`。

### 体验工具

- `docs/experience/REFERENCE.md`：10 个参照产品，只记放置精度、遮挡处理、选中反馈、哪里假。
- `docs/experience/DOGFOOD.md`：每日 5 分钟，三栏记录，优先记"烦"和"累"。
- `docs/experience/PROTOTYPE-01.md`：三个假设、10 次记录表、kill criteria、结论位。

## 没有改什么

- M0–M3 的功能票保持原样：它们描述的是目标，不是承诺；P0 结论可能让其中一部分改写，但现在改写是猜测。
- ADR-0001/0002 不变：技术选型没有被体验证据推翻，只是被标注为"待验证"。
- 术语表不变：这次没有引入新概念。

## 复核条件

P0 跑完 10 次后，必须回答：

1. 三个假设各自成立、不成立还是部分成立。
2. 触发了哪几条 kill criteria。
3. M1 的 007–012 需要改哪几张、改成什么。
4. §11.4 的阈值是否需要调整，理由是什么。

## 结论

文档从"承诺结果"改成"登记假设 + 定义证伪方式"。这是这次修正唯一重要的变化。
