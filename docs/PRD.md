## 1. 问题陈述

现有天文类 App 把宇宙关在屏幕里：用户看到的是图片和视频，感受不到"这个天体就在我的房间里、和我有空间关系"。而常见的 AR 演示又走向另一个极端：只能放一个模型、只能拖动、放完就无事可做，遮挡穿帮、光照不匹配，新鲜感在 30 秒内耗尽。

用户真正想要的是一个**可探索的空间**，而不是一个漂浮的球：能在真实桌面上看到太阳系运转，能在房间里走动时被星海包围，能亲手拆开并复原天宫一号。这三件事的难度与成本依次上升，必须分阶段验证，不能一次性押注。

> **证据声明**：本文件中所有体验类数字（30 秒闭环、90% 选中、55fps、20cm 漂移、真实感评分）在获得真机记录前都是**假设**，不是承诺。验证方式见 §11.4 与 `docs/experience/PROTOTYPE-01.md`；假设被证伪就改需求，不许改证据。

## 2. 解决方案

SpaceWalker 是一个 iOS 原生 AR 应用（RealityKit），把真实空间作为舞台，按三个阶段递进：

- **A 桌面太阳系**：在桌面/地面锚定一个可交互的太阳系，点选、拖拽、缩放、旋转、拖动时间轴看公转。
- **B 房间星海**：把星点铺满房间，用户走动与转动手机改变视角，用视锥选中星体，不必触摸。
- **C 天宫一号任务**：在房间尺度上拆解、装配并与神舟飞船完成交会对接，附史实信息卡。

三个阶段串行推进（ADR-0002）：A 验证锚定与操纵，B 验证实例化与姿态选中，C 验证拆装与任务玩法。每一阶段独立过门禁后才进入下一阶段。

## 3. 目标与非目标

### 3.1 目标

| 编号 | 目标 | 衡量方式 | 证据等级 |
|---|---|---|---|
| G1 | 30 秒内完成一次"放置 → 选中 → 操纵 → 反馈"闭环 | 首次使用任务测试，无文字提示下完成 | 假设（P0 验证） |
| G2 | A 阶段内容可读、构图可控；B 阶段内容稳定地"长在"真实空间里 | A：首次进入 3s 内看见完整 8 行星 + 太阳，点选成功率 ≥ 90%；B：绕桌一周锚定偏移 ≤ 20cm，遮挡按 003 实测定档 | A：已验证（模拟器 9/9 拾取往返）；B：推断 |
| G3 | 交互不只靠触摸：B 阶段用设备姿态完成选中 | 关闭触摸后仍能完成一次选中 | 假设（M2 验证） |
| G4 | 每阶段可独立演示、独立验收 | 每阶段有可运行构建 + 门禁证据 | 事实（流程要求） |
| G5 | A/B 平均 ≥ 55fps（下限 30fps）；C 平均 ≥ 25fps（下限 20fps） | 真机 30 秒录屏 + 帧率统计 | 假设（M1/M2 实测） |

### 3.2 非目标

- 不做天文科普大全，不做完整星表或真实天体力学模拟。
- 不做多人联机、账号体系、云同步。
- 不做 visionOS、Android、Web 版本。
- 不在 C 阶段之前引入外部 3D 资产管线或美术外包。
- 不做应用内购买与 App Store 上架流程（1.0 之前）。

## 4. 用户与场景

### 4.1 用户

| 角色 | 描述 | 关键诉求 |
|---|---|---|
| 主用户（Tang） | 开发者本人，基准机型 iPhone 16 / iOS 26.6 | 验证技术可行性与体验上限，能看到真实性能数据 |
| 首次使用者 | 第一次打开应用、未读任何说明的人 | 30 秒内知道"对准桌面、点一下、拖一下" |
| 体验用户 | 对太空题材感兴趣的 iPhone 用户 | 内容有可看性，不只是一个技术演示 |
| 评审者 | 产品/技术评审 | 需求可验收、风险有缓解、范围可控；不产生用户故事 |

### 4.2 使用场景

| 维度 | 约束 |
|---|---|
| 环境 | 室内，桌面或地面，光照 100–1000 lux，避免强逆光 |
| 空间 | A 阶段 1m×1m 桌面；B 阶段生成半径 3m、允许走动至半径 4m（约 4m×4m 活动区）；C 阶段 1m×1m 桌面 |
| 姿态 | 单人、单手操作，允许绕桌走动 |
| 设备 | 支持 ARKit 的 iPhone，iOS 26.0+；基准机型 iPhone 16 Pro（有 LiDAR）；1.0 仅 iPhone（2026-11-07 决策） |
| 时长 | 单次 3–10 分钟 |

### 4.3 非场景

户外强光、多人协作、交通工具上、无平面检测能力的设备、需要精确测量尺寸的专业场景。

## 5. 产品路线

| 阶段 | 体验一句话 | 空间尺度 | 核心能力 | 内容量 | 退出条件 | 失败止损 |
|---|---|---|---|---|---|---|
| A 桌面太阳系 | 桌面上转着一个能拆看的太阳系 | 0.6–1.2m | 平面锚定、实体操纵、时间轴、信息卡 | 太阳 + 8 行星 | M1 门禁全过 | 交互不成立则回到方案层，不进入 B |
| B 房间星海 | 走两步，星海跟着视角流动 | 生成半径 3m，活动 4m | 实例化星点、视锥选中、LOD、空间音频 | 2000 星点（可调） | M2 门禁全过 | 漂移不可收敛则降级为桌面尺度星海 |
| C 天宫一号 | 把目标飞行器拆开，再让神舟对接上去 | 1:20，主体约 0.52m | 拆解/装配、规则吸附、对接任务、任务卡 | 1 场景 + 3 任务 | M3 门禁全过 | 对接手感不成立则退化为"引导式对接" |

阶段之间是**单向依赖**：A 的锚定与操纵是 B 的前提；B 的实例与姿态选中是 C 的前提。任一阶段门禁未过，不进入下一阶段。

## 6. 用户故事

### 跨阶段

1. 作为首次使用者，我想在启动后立刻知道要把手机对准桌面，以便不用读说明就开始。
2. 作为首次使用者，我想在拒绝相机权限后看到清楚的解释和"去设置"入口，以便知道如何恢复。
3. 作为使用者，我想在设备能力不足时看到"降级模式"提示，以便理解为什么没有遮挡或阴影。
4. 作为使用者，我想在切后台、来电后回到应用时内容还在原位，以便不重复放置。
5. 作为使用者，我想在锚点丢失时被提示"重新放置"，以便不面对一个漂移的物体。
6. 作为使用者，我想一键重置当前场景，以便从混乱状态回到初始布局。
7. 作为 VoiceOver 用户，我想听到当前选中对象的名称与类型（A 天体 / B 星体 / C 模块），以便不依赖视觉。
8. 作为使用者，我想在任何阶段看到当前处于哪个模式（触摸/姿态），以便知道怎么操作。

### A 阶段

9. 作为使用者，我想打开应用就看见一个完整可读的太阳系，以便不用先扫描桌面。
10. 作为使用者，我想把太阳系"放进"自己的房间，以便在真实空间里看它（可选入口）。
11. 作为使用者，我想轻点某颗行星就选中它，以便查看它的信息。
12. 作为使用者，我想拖动选中的天体改变位置，以便调整构图。
13. 作为使用者，我想双指捏合缩放整个太阳系，以便在"看全貌"和"看细节"之间切换。
14. 作为使用者，我想双指旋转太阳系，以便从不同角度观察轨道。
15. 作为使用者，我想拖动时间轴看行星公转，以便直观理解周期差异。
16. 作为使用者，我想暂停时间轴，以便停在某个相位仔细观察。
17. 作为使用者，我想在选中天体时看到名称、类型、直径、距日距离和一句话介绍，以便获得最少必要知识。
18. 作为使用者，我想让信息卡不遮挡选中的天体，以便边看边读。
19. 作为使用者，我想让行星按"可读性优先"的非真实比例呈现，并明确标注这一点，以便不被错误比例误导。
20. 作为使用者，我想在太阳系被缩得太小或拖出视野时被限制，以便不丢失内容。

### B 阶段

21. 作为使用者，我想举起手机就看见真实星表构成的星空，以便不用对着空气想象。
22. 作为使用者，我想转动手机时星空跟着转动，以便像透过一扇舷窗看天。
23. 作为使用者，我想把屏幕中心的准星对准某颗星并停留片刻就选中它，以便不用精确点击。
24. 作为使用者，我想直接点一下星星也能选中，以便在公共场合安静操作。
25. 作为使用者，我想看到恒星的专名、星座、星等与色指数，以便知道自己在看什么。
26. 作为使用者，我想让亮星更大更亮、暗星更小，以便一眼看出星等的差异。
27. 作为使用者，我想让蓝白星与橙红星在颜色上区分开，以便看出恒星温度。
28. 作为使用者，我想一键回到初始视角，以便迷路后不慌。
29. 作为 VoiceOver 用户，我想听到当前准星指向的星名与星等，以便不看屏幕也能确认。

### C 阶段

30. 作为使用者，我想看到按史实标注的天宫一号（目标飞行器/空间实验室），以便学到正确的信息。
31. 作为使用者，我想把太阳翼、实验舱、资源舱分离出来，以便理解它的结构。
32. 作为使用者，我想把模块装回正确接口并听到吸附反馈，以便获得"装对了"的确认。
33. 作为使用者，我想在装错接口时感到排斥反馈，以便自己纠正。
34. 作为使用者，我想控制神舟飞船靠近对接口，并在容差内完成对接，以便体验交会对接的核心难点。
35. 作为使用者，我想在对接失败时看到失败原因并重试，以便从错误中学习。
36. 作为使用者，我想查看每个模块的真实参数与任务历史，以便把玩法和知识连起来。
37. 作为使用者，我想一键重玩整个任务，以便重复体验。
38. 作为 VoiceOver 用户，我想听到当前模块名称与接口状态，以便完成装配任务。

## 7. 功能需求

> 优先级：P0 = 门禁必须通过；P1 = 本阶段应做，可延后一个迭代；P2 = 增强项，可砍。

### 7.1 跨阶段

**FR-X-01 [P0] 相机权限**
- 行为：首次进入 AR 视图时请求相机权限；被拒绝时显示解释页与"去设置"按钮，不进入黑屏。
- 验收：拒绝后再次进入仍显示解释页；从设置授权后返回可正常进入。

**FR-X-02 [P0] 能力探测与降级**
- 行为：启动追踪会话后读取 `UnavailableCapabilities`；不支持遮挡/物理/阴影时关闭对应能力，HUD 标注"降级模式"。
- 验收：真机日志打印可用/不可用能力清单；模拟降级路径的单元测试通过；任何情况下不崩溃、不黑屏。

**FR-X-03 [P0] 会话生命周期**
- 行为：进入后台、来电、锁屏时停止会话与渲染；回到前台重新运行会话；恢复失败时提示重新放置。
- 验收：连续 5 次前后台切换不崩溃；恢复后绕桌一周偏移 ≤ 20cm（NFR-10）。
- 说明：会话只有 run/stop，没有暂停语义；不承诺 ARWorldMap 级重定位。

**FR-X-04 [P0] 锚点丢失恢复**
- 行为：检测到锚点失效或追踪质量骤降时，暂停交互并提示"重新放置"；保留用户已调参数。
- 验收：遮挡相机 5 秒后恢复，提示出现且可一键重放。

**FR-X-05 [P1] 状态 HUD**
- 行为：显示当前阶段、选中对象、模式（触摸/姿态）、能力模式（完整/降级）、帧率（调试构建）。
- 验收：HUD 不遮挡主要交互区域；可一键隐藏。

**FR-X-06 [P0] 重置**
- 行为：重置场景布局、选中态、时间轴与缩放；不重置权限与能力状态。
- 验收：重置后与首次放置状态一致。

**FR-X-07 [P1] 可访问性**
- 行为：VoiceOver 可读出选中对象名称、类型与操作提示（A/B/C 三阶段均覆盖）；信息卡支持动态字体；颜色不是唯一区分手段。
- 验收：开启 VoiceOver 可完成 A 的一次选中与信息卡阅读、B 的一次锁定、C 的一次装配。

### 7.2 A 阶段：桌面太阳系

**FR-A-01 [P1] 可选的房间放置**
- 行为：默认以虚拟相机 + 星系天空盒呈现太阳系，零依赖；用户主动点「放进房间」才进入 AR：检测水平面、显示落点准星、轻点放置；平面不足时提示"移动手机扫描桌面"。
- 验收：默认路径不需要相机权限、不启动 ARKit；AR 路径在木质桌面与地板上各成功放置 3 次，偏差 < 5cm；AR 失败可一键退回虚拟视图且不丢失时间轴状态。

**FR-A-02 [P0] 太阳系内容**
- 行为：太阳 + 8 行星，程序化材质；轨道线可开关；行星直径与轨道半径采用非线性压缩，明确标注"非真实比例"。
- 验收：9 个天体齐全；相对顺序、颜色、土星光环正确；标注可见。

**FR-A-03 [P0] 选中**
- 行为：轻点命中天体；选中态高亮 + 名称标签 + 触觉反馈；再次点空白取消。
- 验收：世界坐标下的可点区域换算到屏幕不小于 44pt；多候选取最近者。
- 遮挡处理 [P1]：有场景网格时剔除被现实物体遮挡的天体；基准机型有 LiDAR，遮挡效果待 003 真机验证后再定优先级，未达标则退化为距离排序。

**FR-A-04 [P0] 操纵**
- 行为：单指拖动移动选中天体；双指捏合缩放整体；双指旋转绕竖直轴旋转；限制最小/最大尺度与最低高度。
- 验收：缩放范围 0.3x–3x；拖到桌面以下被约束；连续拖动 5 秒，相邻帧位置变化无反向抖动（单帧回退 < 2mm）。
- 说明：`ManipulationComponent` 在 iOS 不可用（visionOS 26+），交互由手势 + 变换解算实现。

**FR-A-05 [P0] 信息卡**
- 行为：选中后显示 2D 卡片：名称、类型、直径、距日距离、一句话介绍；可关闭；位置避开选中天体。
- 验收：卡片与选中天体的屏幕投影不重叠；数据与附录 A 一致。

**FR-A-06 [P0] 时间轴**
- 行为：滑块控制模拟天数/秒（默认 1 天/秒，范围 0.1–30 天/秒）；支持暂停/继续；公转相位按真实周期比例。
- 验收：水星明显快于海王星；暂停后相位不变；切换选中不重置时间轴。

**FR-A-07 [P1] 尺度与构图保护**
- 行为：轨道相机距离与俯仰角限制；视线压到轨道面以下时软约束；相机过近时淡出近处天体避免穿模。
- 验收：随机 50 组旋转/缩放操作后内容仍在视野或可一键找回（重置视角按钮）；无穿模。

### 7.3 B 阶段：举机观星（ADR-0004 重写）

> 原「房间星海」方案作废：恒星在无穷远，走动视差为零；把星点放在 3 米又会让它们看起来像室内漂浮粒子。房间追踪买不到这个体验，却要付出全部 AR 风险。改以设备姿态驱动视角，不依赖相机与房间。

**FR-B-01 [P0] 真实星表**
- 行为：内置 HYG v4.1 子集（视星等 ≤ 5.5 且有专名的全部保留），J2000 赤道坐标；按星等分 6 桶合并为网格，桶内使用统一色温。
- 验收：加载 2996 颗；赤道坐标换算后单位向量长 1；分桶后总数不变；星表层单帧 draw call ≤ 10（7 个：6 个星等桶 + 1 个背景桶；星座线、星官、星群各合并为一条，不计入此数）。
- 数据来源与许可见 `docs/assets/NASA-ASSETS.md`。

**FR-B-02 [P0] 姿态驱动视角**
- 行为：`CMDeviceMotion` 姿态 → 视线方向 → 星空反向旋转；俯仰 ±77° 夹取；无陀螺仪（模拟器）时只能拖动。
- 切换：姿态可用时提供「跟随 / 手动」开关。定位（找星跳转、分组聚焦、重置视角）一律切到手动并交出控制权，否则会出现「姿态被锁定、拖动又不可用」的僵局；切回跟随时按当前姿态立即对齐。没有陀螺仪的机器恒为手动，不显示该开关。
- 验收：转动手机星空连续跟随不跳变；俯仰到边界不翻面；模拟器可拖动复现；定位后立刻可拖动；切换开关后朝向在 1 帧内按新模式生效。

**FR-B-03 [P0] 准星选中**
- 行为：屏幕中心 44pt 准星（半径 22pt）；命中判定用屏幕投影距离；停留 0.6s 触发；直接轻点亦可选中；点空白取消。
- 口径：准星内部把 22pt 按投影焦距换算成等价角距（`atan(r / f)`，`f = (屏高/2) / tan(fov/2)`），因此准星与点选在圈边上判定一致。不用线性近似——60° 视场下线性近似会把 1.708° 算成 1.549°，圈边的星会被准星拒绝而点选接受。
- 范围：有专名且视星等 ≤ 4.5 的 288 颗可选中，其余 2708 颗仅作背景（v0.6.1）。
- 停留判定需满足：换目标重新计时；丢失目标按时间衰减而非瞬间归零；触发后须离开目标才可再次触发。
- 验收：命名星体逐个对准可取回自身；误选（指向 A 得到 B）为 0；触摸与准星两条路径结果一致。

**FR-B-04 [P0] 恒星信息卡**
- 行为：显示专名、星座、视星等、赤经赤纬、色指数含义；未命名星显示「未命名恒星」。
- 验收：字段与星表一致；色指数文案不出现「温度」的数值承诺（仅方向性描述）。

**FR-B-05 [P1] 时间与地点对齐**
- 行为：引入恒星时与观测位置，使星图对应「今夜此刻」的真实天空；未授权定位时跳过并保持赤道坐标。
- 验收：同一时刻同一地点，北极星高度角与纬度误差 ≤ 2°（高度由重力方向决定，可达成）；未授权时不阻塞主流程。
- 方位限制：绝对方位依赖磁力计航向，实测精度约 25°，**不承诺东西向对得准**。界面必须标注「方位为估算，可画 8 字或手动朝北校准」，不得暗示星图已与真实方位严格对齐。

**FR-B-06 [P0] 性能预算**
- 行为：2996 颗星、无后处理；平均 ≥ 55fps、下限 30fps；连续 10 分钟无过热降频。
- 验收：真机 30 秒平均 ≥ 55fps；切换视角无卡顿尖峰。

### 7.4 C 阶段：天宫一号任务

**FR-C-01 [P0] 场景与史实**
- 行为：按 1:20 展示尺度呈现天宫一号（实验舱 + 资源舱 + 太阳翼）与神舟飞船，采用程序化材质（2026-11-07 决策）；信息卡标注：2011-09-29 发射、目标飞行器/空间实验室、与神舟八/九/十号共 6 次交会对接、2016-03-16 终止数据服务、2018-04-02 再入。
- 来源：史实完整条目与出处见 `docs/research/realitykit-ios26-primary-sources.md`，本需求只保留展示所需摘要。
- 验收：所有史实条目与一手来源一致；界面不称其为"空间站"。

**FR-C-02 [P0] 拆解**
- 行为：选中模块后可分离（太阳翼、实验舱、资源舱）；分离带缓动与音效；分离后的模块保持悬浮可选中。
- 验收：三个模块均可分离与选中；分离不导致穿模或丢失；分离后 10 秒内可重新选中。

**FR-C-03 [P0] 装配**
- 行为：模块靠近正确接口时按"距离 + 轴夹角 + 接口 ID"规则判定，判定通过后动画吸附并锁定；错误接口产生排斥与提示；装配完成触发合拢动画。
- 验收：三个模块均可正确复位；错误接口 100% 被拒绝；判定不依赖物理引擎的随机结果。

**FR-C-04 [P0] 对接任务**
- 行为：六自由度控制神舟飞船靠近对接口；成功后保持 1 秒判定完成。
- 输入映射：单指拖动 = 横向/纵向平移；双指捏合 = 轴向推进/后退；双指旋转 = 俯仰/偏航微调；长按 = 切换粗调/精调。
- 成功容差（1:20 展示尺度）：接近速度 ≤ 0.02m/s、轴向偏差 ≤ 2cm、姿态偏差 ≤ 5°、角速度 ≤ 5°/s。
- 失败原因：过快、偏角过大、撞偏、超时（90 秒）。
- 验收：成功路径可复现；四类失败均可触发并给出对应原因。

**FR-C-05 [P0] 任务卡**
- 行为：显示任务目标、步骤、进度、失败原因与重试入口。
- 验收：每步状态纯本地可复现，不依赖网络。

**FR-C-06 [P1] 重玩**
- 行为：一键重置任务到初始状态，保留已解锁的史实卡片。
- 验收：重玩 3 次无状态残留。

## 8. 交互规范

### 8.1 输入映射

| 输入 | A 阶段 | B 阶段 | C 阶段 | 反馈 |
|---|---|---|---|---|
| 单指轻点 | 选中天体（FR-A-03） | 选中星点（触摸模式，FR-B-02） | 选中模块（FR-C-02） | 高亮 + 触觉 |
| 单指拖动 | 移动选中天体（FR-A-04） | 环视，不移动星海（FR-B-04） | 平移飞船（FR-C-04） | 跟手 + 边界约束 |
| 双指捏合 | 缩放整体（FR-A-04） | 调整星点密度（FR-B-01） | 轴向推进（FR-C-04） | 连续无跳变 |
| 双指旋转 | 绕竖直轴旋转（FR-A-04） | 无 | 俯仰/偏航微调（FR-C-04） | 可选 15° 吸附 |
| 长按 | 信息卡（FR-A-05） | 无 | 粗调/精调切换（FR-C-04） | 200ms 后触发 |
| 设备姿态 | 无 | 视锥选中（FR-B-02） | 飞船姿态微调（FR-C-04） | 准星 + 音频 |

### 8.2 命中规则

- A/C：只有带 `CollisionComponent` 与 `InputTargetComponent` 的实体参与命中；多候选取距相机最近者。
- B：星点为 `MeshInstances` 实例，非实体；用屏幕投影 + 射线-球解析判定，不经过碰撞组件。
- 最小命中区域 44pt；世界尺寸按相机距离逐帧换算，不使用固定世界尺寸。
- 被遮挡实体是否参与，取决于场景网格可用性；基准机型有 LiDAR，仍以真机验证为准，未达标则退化为距离排序。

### 8.3 反馈规范

- 选中：100ms 内出现高亮、名称与触觉。
- 操纵：触摸事件到 transform 更新 ≤ 50ms（不含显示链路）；松手后 200ms 内完成吸附。
- 错误：排斥/拒绝反馈 ≤ 300ms，附一句原因。
- 音频：空间音频仅用于 B/C；A 阶段只用触觉，避免噪音。

### 8.4 约束

- 同一帧只允许一个主交互（拖动/缩放/旋转互斥）。
- 任何手势不得同时改变相机与实体（B 阶段姿态模式除外）。
- 所有可交互对象必须有可读名称，供 VoiceOver 使用。

## 10. 技术决策

本节只列约束摘要，选型理由与替代方案见 `docs/adr/ADR-0001`、`ADR-0002`。

- **视图层**：SwiftUI + `RealityView`。两套相机模式：A 阶段默认 `camera: .virtual` + `environment: .skybox(...)`（无 ARKit、无权限、可在模拟器验证）；「放进房间」与 B 阶段使用 `camera: .spatialTracking`。
- **天空盒**：NASA/Goddard SVS《Deep Star Maps 2020》4096×2048 等距柱状图，构建期由 OpenEXR 线性 HDR 经 +0.35EV / 对比 1.18 转 sRGB JPEG；加载失败时回退到程序化星系（见 `docs/assets/NASA-ASSETS.md`）。
- **会话层**：`SpatialTrackingSession`（iOS 18+；本项目部署目标 26，按 `MeshInstancesComponent` 的下限取高），启动后读 `UnavailableCapabilities`，按能力矩阵降级（ADR-0001）。
- **交互层**：iOS 没有 `ManipulationComponent`（visionOS 26+），拖拽/缩放/旋转用 SwiftUI 手势 `.targetedToAnyEntity()` + `CollisionComponent` + `InputTargetComponent` + 自行解算 Transform。
- **遮挡层**：iOS 没有 `EnvironmentBlendingComponent`（visionOS 26+），现实遮挡依赖 `sceneUnderstanding: [.occlusion]`；基准机型有 LiDAR，效果待真机验证，达标后可上调承诺。
- **实例层**：`MeshInstancesComponent`（iOS 26+）承载星海；实例不是 `Entity`，不参与碰撞与命中，命中走解析判定。
- **状态层**：单一应用状态（阶段、选中、模式、时间轴、能力模式）；渲染更新收敛到主 actor；每帧逻辑用系统处理。
- **数据**：天体与天宫一号参数为本地静态数据，不依赖网络；史实条目附来源。
- **测试缝**（由高到低）：
  1. 能力矩阵：输入能力清单 → 输出降级配置（纯函数）。
  2. 选中判定：输入候选集 + 射线/视锥 → 输出选中对象（纯函数）。
  3. 时间轴：输入模拟天数 → 输出各天体相位（纯函数）。
  4. 星点布局：输入种子 + 数量 + 半径 → 输出实例变换（纯函数，可快照）。
  5. 对接判定：输入位置/姿态/速度 → 输出成功或失败原因（纯函数）。
- **不可自动化**：追踪质量、遮挡效果、真机帧率、热行为，只能真机门禁验证。

|---|---|---|---|

| M3 | C 阶段可玩 | 同上 + 史实核对 | 3–4 个迭代 |
