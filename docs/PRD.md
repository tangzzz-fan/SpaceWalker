## 1. 问题陈述

现有天文类 App 把宇宙关在屏幕里：用户看到的是图片和视频，感受不到"这个天体就在我的房间里、和我有空间关系"。而常见的 AR 演示又走向另一个极端：只能放一个模型、只能拖动、放完就无事可做，遮挡穿帮、光照不匹配，新鲜感在 30 秒内耗尽。

用户真正想要的是一个**可探索的空间**，而不是一个漂浮的球：能在真实桌面上看到太阳系运转，能在房间里走动时被星海包围，能亲手拆开并复原天宫一号。这三件事的难度与成本依次上升，必须分阶段验证，不能一次性押注。

> **2026-11-07 路径变更（v0.9/v0.10）**：上面这段是**产品意图**——「在我所在的空间里」，不是技术方案。实际实现已全部退出 AR：A 走虚拟相机 + 星系天空盒（ADR-0003），B 走设备姿态 + 真实星表（ADR-0004），C 在虚拟视图验收（ticket 063）。应用当前**不请求相机权限、不启动 ARKit**。下文凡出现平面锚定、相机权限、`spatialTracking`、遮挡网格的表述，一律按 §7.1「已移除」条目理解。

> **证据声明**：本文件中所有体验类数字（30 秒闭环、90% 选中、55fps、20cm 漂移、真实感评分）在获得真机记录前都是**假设**，不是承诺。验证方式见 §11.4 与 `docs/experience/PROTOTYPE-01.md`；假设被证伪就改需求，不许改证据。

## 2. 解决方案

SpaceWalker 是一个 iOS 原生 AR 应用（RealityKit），把真实空间作为舞台，按三个阶段递进：

- **A 太阳系**：以虚拟相机 + 星系天空盒呈现可交互的太阳系，点选、拖拽、缩放、旋转、拖动时间轴看公转（ADR-0003）。
- **B 举机观星**：内置真实星表，用设备姿态驱动视角，准星停留选中星体，也可直接触摸（ADR-0004）。
- **C 天宫一号任务**：1:20 程序化几何的拆解、装配与神舟交会对接，附史实信息卡；**界面质量本身是验收项**（FR-C-07）。

三个阶段串行推进（ADR-0002）：A 验证内容呈现与操纵，B 验证姿态选中与实例化，C 验证拆装、任务玩法与视觉表达。每一阶段独立过门禁后才进入下一阶段。

## 3. 目标与非目标

### 3.1 目标

| 编号 | 目标 | 衡量方式 | 证据等级 |
|---|---|---|---|
| G1 | 30 秒内完成一次"放置 → 选中 → 操纵 → 反馈"闭环 | 首次使用任务测试，无文字提示下完成 | 假设（P0 验证） |
| G2 | A 阶段内容可读、构图可控；B 阶段星空稳定地跟随手腕；C 阶段模型经得起近看 | A：首次进入 3s 内看见完整 8 行星 + 太阳，点选成功率 ≥ 90%；B：姿态跟随无跳变、俯仰到边界不翻面；C：不读标签盲测 ≥ 4/5 认出天宫一号（X-07） | A：已验证（模拟器 9/9 拾取往返）；B：已验证（M2）；C：待 M3.1 |
| G3 | 交互不只靠触摸：B 阶段用设备姿态完成选中 | 关闭触摸后仍能完成一次选中 | 假设（M2 验证） |
| G4 | 每阶段可独立演示、独立验收 | 每阶段有可运行构建 + 门禁证据 | 事实（流程要求） |
| G5 | A/B 平均 ≥ 55fps（下限 30fps）；C 平均 ≥ 25fps（下限 20fps） | 真机 30 秒录屏 + 帧率统计 | 假设（M1/M2 实测） |

### 3.2 非目标

- 不做天文科普大全，不做完整星表或真实天体力学模拟。
- 不做多人联机、账号体系、云同步。
- 不做 visionOS、Android、Web 版本。
- 不引入外部 3D 资产管线与美术外包；C 阶段已按 ADR-0005 复核，仍走程序化几何 + 程序化贴图。
- 不做应用内购买与 App Store 上架流程（1.0 之前）。

## 4. 用户与场景

### 4.1 用户

| 角色 | 描述 | 关键诉求 |
|---|---|---|
| 主用户（Tang） | 开发者本人，基准机型 iPhone 16 Pro / iOS 26.6（以门禁证据为准） | 验证技术可行性与体验上限，能看到真实性能数据 |
| 首次使用者 | 第一次打开应用、未读任何说明的人 | 30 秒内知道"对准桌面、点一下、拖一下" |
| 体验用户 | 对太空题材感兴趣的 iPhone 用户 | 内容有可看性，不只是一个技术演示 |
| 评审者 | 产品/技术评审 | 需求可验收、风险有缓解、范围可控；不产生用户故事 |

### 4.2 使用场景

| 维度 | 约束 |
|---|---|
| 环境 | 任意；虚拟视图自带光照与背景，不依赖环境光，户外强光不再是约束 |
| 空间 | 手持即可，不需要活动空间；A/C 是屏幕内的近距内容（等效 0.6–1.2m 构图），B 是无穷远星场 |
| 姿态 | 单人、单手操作；B 允许边走边转手机 |
| 设备 | iPhone，iOS 26.0+；基准机型 iPhone 16 Pro（iOS 26.6）；**不要求 LiDAR 与 ARKit**；1.0 仅 iPhone（2026-11-07 决策） |
| 时长 | 单次 3–10 分钟 |

### 4.3 非场景

多人协作、交通工具上、需要精确测量尺寸的专业场景；户外强光与「无平面检测能力的设备」已不再是约束——应用不使用相机与平面检测。

## 5. 产品路线

| 阶段 | 体验一句话 | 空间尺度 | 核心能力 | 内容量 | 退出条件 | 失败止损 |
|---|---|---|---|---|---|---|
| A 太阳系 | 屏幕上转着一个能拆看的太阳系 | 等效 0.6–1.2m | 虚拟相机、实体操纵、时间轴、信息卡 | 太阳 + 8 行星 | M1 门禁全过 | 交互不成立则回到方案层，不进入 B |
| B 举机观星 | 举起手机，星空跟着手腕转动 | 无穷远（赤道坐标） | 真实星表、姿态跟随、准星选中、LOD | 2996 星（288 可选中） | M2 门禁全过 | 姿态抖动不可收敛则改为「准星 + 轻点确认」混合 |
| C 天宫一号 | 把目标飞行器拆开，再让神舟对接上去 | 1:20，主体约 0.52m | 拆解/装配、规则吸附、对接任务、任务卡、**四层视觉精细度** | 1 场景 + 3 任务 | M3 + M3.1 门禁全过 | 对接手感不成立则退化为"引导式对接" |

阶段之间是**单向依赖**：A 的呈现与操纵是 B 的前提；B 的实例与姿态选中是 C 的前提。任一阶段门禁未过，不进入下一阶段。

## 7. 功能需求

> 优先级：P0 = 门禁必须通过；P1 = 本阶段应做，可延后一个迭代；P2 = 增强项，可砍。

### 7.1 跨阶段

> **v0.10 变更**：FR-X-01..04 是 AR 会话期的 P0 需求，随 v0.9（ticket 063）删除相机与追踪链路后**已无可执行对象**，编号保留为已移除，不再计入任何门禁。它们曾覆盖的「不崩溃、不黑屏」纪律由 FR-X-03' 承接。

**~~FR-X-01 [P0] 相机权限~~ [已移除 2026-11-07]**
- 原行为：首次进入 AR 视图时请求相机权限；被拒绝时显示解释页与"去设置"按钮。
- 移除理由：应用不再请求相机（FR-A-01 移除说明）。`Permission` / `PermissionCopy` 整条链路已删除。

**~~FR-X-02 [P0] 能力探测与降级~~ [已移除 2026-11-07]**
- 原行为：读 `UnavailableCapabilities`，不支持遮挡/物理/阴影时降级并标注"降级模式"。
- 移除理由：虚拟相机没有能力矩阵可探测。

**~~FR-X-03 [P0] 会话生命周期~~ [已移除 2026-11-07]**
- 原行为：前后台、来电、锁屏时停止并恢复追踪会话。
- 移除理由：没有 `SpatialTrackingSession`。

**~~FR-X-04 [P0] 锚点丢失恢复~~ [已移除 2026-11-07]**
- 原行为：锚点失效或追踪质量骤降时提示"重新放置"。
- 移除理由：没有锚点。

**FR-X-03' [P0] 路由往返不黑屏（承接 X-01..04 的纪律）**
- 行为：在 A/B/C 三个路由之间切换时，每次进入都重建渲染树并重新挂载；不允许复用上一轮的 root 实体。
- 验收：A→C→A→C 往返 4 次，每次截图都非黑屏；判据可用文件大小辅助（黑屏约 368 KB，有画面约 2.8 MB）。
- 依据：`RealityView` 每次重建都会给出新的 `RealityViewCameraContent`，复用 root 二次 `add` 不生效，先 `removeFromParent()` 也不行（ticket 1219179）。

**FR-X-05 [P1] 状态 HUD**
- 行为：显示当前阶段、选中对象、模式（触摸/姿态）、帧率（调试构建）。
- 验收：HUD 不遮挡主要交互区域；可一键隐藏。

**FR-X-06 [P0] 重置**
- 行为：重置场景布局、选中态、时间轴与缩放；不重置内容装载状态。
- 验收：重置后与首次进入的状态一致。

**FR-X-07 [P1] 可访问性**
- 行为：VoiceOver 可读出选中对象名称、类型与操作提示（A/B/C 三阶段均覆盖）；信息卡支持动态字体；颜色不是唯一区分手段。
- 验收：开启 VoiceOver 可完成 A 的一次选中与信息卡阅读、B 的一次锁定、C 的一次装配。

### 7.2 A 阶段：太阳系（虚拟视图）

**FR-A-01 [暂移除] 可选的房间放置**
- 行为：默认以虚拟相机 + 星系天空盒呈现太阳系，零依赖。
- **2026-11-07 决策：AR 入口整体移除**。原因：iOS 26 上「父视图有 RealityView + `fullScreenCover` 内再建 `.spatialTracking`」的组合会让相机画面全黑（Apple 论坛 786543，Apple 工程师确认需提 FB）；实测相机已授权、ARKit 平面检测正常，但 passthrough 不渲染。两次绕行尝试（卸载底层 RealityView、改同层覆盖）均无效且导致退出 AR 后太阳系空白，已回退。
- 因此应用当前**不请求相机权限、不启动 ARKit**，`SessionView` / `PlacementController` / `Permission` 整条链路已删除（可经 git 历史恢复）。
- 恢复条件：Apple 修复该回归，或改用 `ARView`（UIKit 路径 + 显式 session）并能自证 passthrough 渲染。恢复后本条从 P1 重新评估。

**FR-A-02 [P0] 太阳系内容**
- 行为：太阳 + 8 行星，程序化材质；轨道线可开关；行星直径与轨道半径采用非线性压缩，明确标注"非真实比例"。
- 验收：9 个天体齐全；相对顺序、颜色、土星光环正确；标注可见。

**FR-A-03 [P0] 选中**
- 行为：轻点命中天体；选中态高亮 + 名称标签 + 触觉反馈；再次点空白取消。
- 验收：世界坐标下的可点区域换算到屏幕不小于 44pt；多候选取最近者。
- 遮挡处理 [已作废 2026-11-07]：原按场景网格剔除被现实物体遮挡的天体。虚拟视图没有场景网格，改为「距离排序 + 近处天体淡出」，避免穿模（FR-A-07）。

**FR-A-04 [P0] 操纵**
- 行为：单指拖动移动选中天体；双指捏合缩放整体；双指旋转绕竖直轴旋转；限制最小/最大尺度与最低高度。
- 验收：缩放范围 0.3x–3x；拖到桌面以下被约束；连续拖动 5 秒，相邻帧位置变化无反向抖动（单帧回退 < 2mm）。
- 说明：`ManipulationComponent` 在 iOS 不可用（visionOS 26+），交互由手势 + 变换解算实现。

**FR-A-05 [P0] 信息卡**
- 行为：选中后显示 2D 卡片：名称、类型、直径、距日距离、一句话介绍；可关闭；位置避开选中天体。
- 验收：卡片与选中天体的屏幕投影不重叠；数据与附录 A 一致。

**FR-A-06 [P0] 时间轴**
- 行为：滑块控制模拟天数/秒（默认 1 天/秒，范围 0.1–30 天/秒）；支持暂停/继续；公转相位按真实周期比例。
- 验收：水星明显快于海王星；暂停后相位不变；切换选中不重置时间轴。

**FR-A-07 [P1] 尺度与构图保护**
- 行为：轨道相机距离与俯仰角限制；视线压到轨道面以下时软约束；相机过近时淡出近处天体避免穿模。
- 验收：随机 50 组旋转/缩放操作后内容仍在视野或可一键找回（重置视角按钮）；无穿模。

### 7.3 B 阶段：举机观星（ADR-0004 重写）

> 原「房间星海」方案作废：恒星在无穷远，走动视差为零；把星点放在 3 米又会让它们看起来像室内漂浮粒子。房间追踪买不到这个体验，却要付出全部 AR 风险。改以设备姿态驱动视角，不依赖相机与房间。

**FR-B-01 [P0] 真实星表**
- 行为：内置 HYG v4.1 子集（视星等 ≤ 5.5 且有专名的全部保留），J2000 赤道坐标；按星等分 6 桶合并为网格，桶内使用统一色温。
- 验收：加载 2996 颗；赤道坐标换算后单位向量长 1；分桶后总数不变；星表层单帧 draw call ≤ 10（7 个：6 个星等桶 + 1 个背景桶；星座线、星官、星群各合并为一条，不计入此数）。
- 数据来源与许可见 `docs/assets/NASA-ASSETS.md`。

**FR-B-02 [P0] 姿态驱动视角**
- 行为：`CMDeviceMotion` 姿态 → 视线方向 → 星空反向旋转；俯仰 ±77° 夹取；无陀螺仪（模拟器）时只能拖动。
- 切换：姿态可用时提供「跟随 / 手动」开关。定位（找星跳转、分组聚焦、重置视角）一律切到手动并交出控制权，否则会出现「姿态被锁定、拖动又不可用」的僵局；切回跟随时按当前姿态立即对齐。没有陀螺仪的机器恒为手动，不显示该开关。
- 验收：转动手机星空连续跟随不跳变；俯仰到边界不翻面；模拟器可拖动复现；定位后立刻可拖动；切换开关后朝向在 1 帧内按新模式生效。

**FR-B-03 [P0] 准星选中**
- 行为：屏幕中心 44pt 准星（半径 22pt）；命中判定用屏幕投影距离；停留 0.6s 触发；直接轻点亦可选中；点空白取消。
- 口径：准星内部把 22pt 按投影焦距换算成等价角距（`atan(r / f)`，`f = (屏高/2) / tan(fov/2)`），因此准星与点选在圈边上判定一致。不用线性近似——60° 视场下线性近似会把 1.708° 算成 1.549°，圈边的星会被准星拒绝而点选接受。
- 范围：有专名且视星等 ≤ 4.5 的 288 颗可选中，其余 2708 颗仅作背景（v0.6.1）。
- 停留判定需满足：换目标重新计时；丢失目标按时间衰减而非瞬间归零；触发后须离开目标才可再次触发。
- 验收：命名星体逐个对准可取回自身；误选（指向 A 得到 B）为 0；触摸与准星两条路径结果一致。

**FR-B-04 [P0] 恒星信息卡**
- 行为：显示专名、星座、视星等、赤经赤纬、色指数含义；未命名星显示「未命名恒星」。
- 验收：字段与星表一致；色指数文案不出现「温度」的数值承诺（仅方向性描述）。

**FR-B-05 [P1] 时间与地点对齐**
- 行为：引入恒星时与观测位置，使星图对应「今夜此刻」的真实天空；未授权定位时跳过并保持赤道坐标。
- 验收：同一时刻同一地点，北极星高度角与纬度误差 ≤ 2°（高度由重力方向决定，可达成）；未授权时不阻塞主流程。
- 方位限制：绝对方位依赖磁力计航向，实测精度约 25°，**不承诺东西向对得准**。界面必须标注「方位为估算，可画 8 字或手动朝北校准」，不得暗示星图已与真实方位严格对齐。

**FR-B-06 [P0] 性能预算**
- 行为：2996 颗星、无后处理；平均 ≥ 55fps、下限 30fps；连续 10 分钟无过热降频。
- 验收：真机 30 秒平均 ≥ 55fps；切换视角无卡顿尖峰。

### 7.4 C 阶段：天宫一号任务

**FR-C-01 [P0] 场景与史实**
- 行为：按 1:20 展示尺度呈现天宫一号（实验舱 + 资源舱 + 太阳翼）与神舟飞船，采用程序化材质（2026-11-07 决策，v0.10 按 ADR-0005 复核仍不变）；信息卡标注：2011-09-29 发射、目标飞行器/空间实验室、与神舟八/九/十号共 6 次交会对接、2016-03-16 终止数据服务、2018-04-02 再入。
- 来源：史实完整条目与出处见 `docs/research/realitykit-ios26-primary-sources.md`，本需求只保留展示所需摘要。
- 验收：
  1. 所有史实条目与一手来源一致；界面不称其为"空间站"。
  2. 正/侧/俯三视角截图与 `reference-tiangong-drawing.png` 并排归档到 `docs/gates/M3/`，结构清单 12 项逐条打勾（见 FR-C-07）。
  3. **盲测 ≥ 4/5 的人在不读任何标签的情况下说出「天宫一号」**（v0.10 新增；这是 062 的降级方案要买回来的东西）。

**FR-C-02 [P0] 拆解**
- 行为：选中模块后可分离（太阳翼 ×2、实验舱、资源舱）；分离带缓动与音效；分离后的模块保持悬浮可选中。
- 验收：四个模块均可分离与选中；分离不导致穿模或丢失；分离后 10 秒内可重新选中。

**FR-C-03 [P0] 装配**
- 行为：模块靠近正确接口时按"距离 + 轴夹角 + 接口 ID"规则判定，判定通过后动画吸附并锁定；错误接口产生排斥与提示；装配完成触发合拢动画。
- 验收：三个模块均可正确复位；错误接口 100% 被拒绝；判定不依赖物理引擎的随机结果。

**FR-C-04 [P0] 对接任务**
- 行为：六自由度控制神舟飞船靠近对接口；成功后保持 1 秒判定完成。
- 输入映射：单指拖动 = 横向/纵向平移；双指捏合 = 轴向推进/后退；双指旋转 = 俯仰/偏航微调；长按 = 切换粗调/精调。
- 成功容差（1:20 展示尺度）：接近速度 ≤ 0.02m/s、轴向偏差 ≤ 2cm、姿态偏差 ≤ 5°、角速度 ≤ 5°/s。
- 失败原因：过快、偏角过大、撞偏、超时（90 秒）。
- 验收：成功路径可复现；四类失败均可触发并给出对应原因。

**FR-C-05 [P0] 任务卡**
- 行为：显示任务目标、步骤、进度、失败原因与重试入口。
- 验收：每步状态纯本地可复现，不依赖网络。

**FR-C-06 [P1] 重玩**
- 行为：一键重置任务到初始状态，保留已解锁的史实卡片。
- 验收：重玩 3 次无状态残留。

**FR-C-07 [P0] 视觉精细度（v0.10 新增）**
- 背景：062 的实体表达盲测不通过（裸看像水管），当时用「5 个常驻标签」补偿。标签只回答"这是哪一段"，不回答"这是什么"。本条把辨识度的责任从文字挪回几何，分四层，**每层可测**。
- L0 结构（剪影正确）：
  - 实验舱 = 前锥段 1.6 m + 圆柱段 4.0 m + 后锥段 0.8 m（合计 6.4 m；分段长度是**视觉分配**，无一手来源，不进史实卡）。
  - 太阳翼每翼 4 块电池板（一手文字「一对 4 块太阳电池板」），带铰链与根部斜撑。
  - 神舟返回舱为钟形，用母线旋转体生成，不用直母线锥台。
  - 断言：分段长度和 = 6.4 m；相邻段端面半径连续（差值 = 0）；每翼格数 = 4。
- L1 分块：环向加强环 ×3、纵向板缝、舷窗、舱门、对接机构（环 + 4 卡爪 + 中心通道）、遥感设备舱口。断言：每模块子件 ≥ 3；对接机构子件 ≥ 3。
- L2 材质：程序化贴图（板缝、电池片网格、金属箔噪声）+ 三档材质（白 MLI 粗糙 0.72 非金属 / 金箔 0.38 金属 0.85 / 电池片 0.28 深蓝）+ 一盏背部冷轮廓光（解黑底上丢轮廓）。断言：材质档 ≥ 3；贴图只生成一次并缓存，不随路由重建重算。
- L3 小件：轨控发动机 2 台 + 备用 4 台 + 姿控喷口、Ø1 m 中继天线抛物面、推进舱发动机 4 台。
- 预算：实体 ≤ 60、三角形 ≤ 20k、draw call ≤ 40。NFR-01 的 C 阶段口径不放宽。
- 验收：L0/L1 的结构断言自动化；预算由几何总量断言守住；真机帧率复测；三视角截图与参考图并排。L2 完成后，部件标签从「常驻」改为「选中显示」。
- **结构清单 12 项**（M3.1 逐条打勾，缺一项不签发）：后锥段、前锥段、圆柱段、太阳翼 4 格、翼根斜撑、对接环、对接卡爪、钟形返回舱、尾部主发动机喷管、抛物面天线、舷窗、板缝与加强环。
- 约束：几何改动只在 `addLab` / `addResource` / `addWing` / `addShenzhou` 内部，不动 `TiangongSession`、装配判定、对接判定与任务状态机——既有 310 项测试必须零改动通过。

## 8. 交互规范

### 8.1 输入映射

| 输入 | A 阶段 | B 阶段 | C 阶段 | 反馈 |
|---|---|---|---|---|
| 单指轻点 | 选中天体（FR-A-03） | 选中星点（触摸模式，FR-B-02） | 选中模块（FR-C-02） | 高亮 + 触觉 |
| 单指拖动 | 移动选中天体（FR-A-04） | 环视，不移动星海（FR-B-04） | 平移飞船（FR-C-04） | 跟手 + 边界约束 |
| 双指捏合 | 缩放整体（FR-A-04） | 调整星点密度（FR-B-01） | 轴向推进（FR-C-04） | 连续无跳变 |
| 双指旋转 | 绕竖直轴旋转（FR-A-04） | 无 | 俯仰/偏航微调（FR-C-04） | 可选 15° 吸附 |
| 长按 | 信息卡（FR-A-05） | 无 | 粗调/精调切换（FR-C-04） | 200ms 后触发 |
| 设备姿态 | 无 | 视锥选中（FR-B-02） | 飞船姿态微调（FR-C-04） | 准星 + 音频 |

### 8.2 命中规则

- A/C：只有带 `CollisionComponent` 与 `InputTargetComponent` 的实体参与命中；多候选取距相机最近者。
- B：星点为 `MeshInstances` 实例，非实体；用屏幕投影 + 射线-球解析判定，不经过碰撞组件。
- 最小命中区域 44pt；世界尺寸按相机距离逐帧换算，不使用固定世界尺寸。
- 虚拟视图没有场景网格，「遮挡」纯粹由深度决定：多候选取距相机最近者，与实体是否被现实物体挡住无关（原「场景网格 / LiDAR」判定已随 v0.9 作废）。

### 8.3 反馈规范

- 选中：100ms 内出现高亮、名称与触觉。
- 操纵：触摸事件到 transform 更新 ≤ 50ms（不含显示链路）；松手后 200ms 内完成吸附。
- 错误：排斥/拒绝反馈 ≤ 300ms，附一句原因。
- 音频：空间音频仅用于 B/C；A 阶段只用触觉，避免噪音。

### 8.4 约束

- 同一帧只允许一个主交互（拖动/缩放/旋转互斥）。
- 任何手势不得同时改变相机与实体（B 阶段姿态模式除外）。
- 所有可交互对象必须有可读名称，供 VoiceOver 使用。

## 10. 技术决策

本节只列约束摘要，选型理由与替代方案见 `docs/adr/ADR-0001`、`ADR-0002`。

- **视图层**：SwiftUI + `RealityView`，**只有一种相机模式**：`camera: .virtual` + `environment: .skybox(...)`。A/B/C 三阶段都在虚拟视图验收（v0.9 起；原「放进房间」与 B 阶段的 `camera: .spatialTracking` 已随 063 删除）。路由往返必须重建渲染树，见 FR-X-03'。
- **天空盒**：NASA/Goddard SVS《Deep Star Maps 2020》4096×2048 等距柱状图，构建期由 OpenEXR 线性 HDR 经 +0.35EV / 对比 1.18 转 sRGB JPEG；加载失败时回退到程序化星系（见 `docs/assets/NASA-ASSETS.md`）。
- **会话层**：没有 `SpatialTrackingSession`、没有能力矩阵、没有锚点。姿态输入走 `CMDeviceMotion`（B 阶段视角、C 阶段飞船微调）；切后台停采样，回前台恢复。采样率由 CoreMotion 量化，实测 `1/60` → 33Hz、`1/120` → 100Hz，**不在代码层修**（056 结论）。
- **交互层**：iOS 没有 `ManipulationComponent`（visionOS 26+），拖拽/缩放/旋转用 SwiftUI 手势 `.targetedToAnyEntity()` + `CollisionComponent` + `InputTargetComponent` + 自行解算 Transform。
- **遮挡层**：已作废。iOS 没有 `EnvironmentBlendingComponent`（visionOS 26+），而 `sceneUnderstanding: [.occlusion]` 需要追踪会话；虚拟视图两样都没有，改用深度排序与近处淡出（FR-A-07）。
- **几何层**：全部 `MeshResource` 程序化生成。`MeshDescriptor` 直出用于旋转体（`TiangongMesh.frustum` 是特例，v0.10 起扩成 `revolve(profile:)`）与星点；贴图用 `CGContext` 画成 `CGImage` 再转 `TextureResource`，不引入图片资源（ADR-0005）。
- **实例层**：`MeshInstancesComponent`（iOS 26+）承载星海；实例不是 `Entity`，不参与碰撞与命中，命中走解析判定。
- **状态层**：单一应用状态（阶段、选中、模式、时间轴、能力模式）；渲染更新收敛到主 actor；每帧逻辑用系统处理。
- **数据**：天体与天宫一号参数为本地静态数据，不依赖网络；史实条目附来源。
- **测试缝**（由高到低）：
  1. 能力矩阵：输入能力清单 → 输出降级配置（纯函数）。
  2. 选中判定：输入候选集 + 射线/视锥 → 输出选中对象（纯函数）。
  3. 时间轴：输入模拟天数 → 输出各天体相位（纯函数）。
  4. 星点布局：输入种子 + 数量 + 半径 → 输出实例变换（纯函数，可快照）。
  5. 对接判定：输入位置/姿态/速度 → 输出成功或失败原因（纯函数）。
- **不可自动化**：真机帧率、热行为、姿态手感、视觉辨识度（盲测），只能真机门禁验证。

### 11.2 阶段门禁

**P0 体验原型**（M0 之前，2 天）：一颗行星的完整闭环（放置 → 选中 → 拖拽 → 信息卡）；10 次真机记录；三个假设有结论；kill criteria 逐条判定。交付：`docs/experience/PROTOTYPE-01.md` 填完 + 10 段录屏索引。未跑完 P0，不开始 M0 工程化。

**~~M0 可行性~~ [已归档]**：原 6 项门禁（会话启动、相机背景、平面锚定、能力清单、拒绝权限、降级路径）全部是 AR 会话项，随 v0.9 作废。当时证据保留在 `docs/gates/M0/`，仅作历史参考，不再作为任何阶段的前置。

**M1 A 阶段**：A 阶段 P0 全过；冷启动到可见太阳系 ≤ 3s；平均帧率 ≥ 55fps；9 天体拾取往返 9/9；路由往返（A↔C）不黑屏；素材来源面板可查。交付：截图/录屏 + 帧率统计 + 已知问题清单。

**M2 B 阶段**：B 阶段 P0 全过；准星选中 288 颗可选中星逐颗居中均可取回自身、误选 0；姿态跟随在手持抖动下无跳变、俯仰到边界不翻面；触摸/姿态可切换且切换后朝向不跳；2996 颗星连续 10 分钟平均 ≥ 55fps、thermal 保持 nominal。交付：截图/录屏 + 帧率与 thermal 统计 + `sky.pickProbe` 往返日志 + 10 分钟连续运行记录。

**M3 C 阶段**：C 阶段 P0 全过；三任务可完成；四类失败原因准确；史实零错误。交付：录屏 + 史实核对表。

**M3.1 视觉精细度（v0.10 新增）**：FR-C-07 四层全过——结构断言（分段和 6.4 / 端面半径连续 / 每翼 4 格）通过；分块清单 12 项无缺项；材质三档到位且贴图只生成一次；小件齐备；实体 ≤ 60、三角形 ≤ 20k、draw call ≤ 40；真机帧率 ≥ 25fps 复测通过；三视角截图与参考图并排；**盲测 ≥ 4/5 不读标签认出天宫一号**。交付：三视角对照图 + 结构清单打勾表 + 盲测记录 + 几何预算日志 + 帧率复测。**M3.1 不过，不进 1.0 内容冻结。**

### 11.3 完成定义（DoD）

- 每条 P0 需求有对应验收记录，且已通过。
- 体验类 P0 需求必须附真机记录（TTFS/疲劳/真实感），不接受"看起来没问题"。
- 无 P0 未决问题；P1 未决问题有明确处理计划。
- 实测证据入库（截图/录屏/日志/帧率）。
- 相关 ADR、术语表、issue 状态同步更新。

### 11.4 体验验收

| 编号 | 指标 | 测法 | 阈值 | 适用 |
|---|---|---|---|---|
| X-01 | 首次成功时间 TTFS | 打开到第一次选中成功 | ≤ 30s | P0 / M1 |
| X-02 | 放弃率 | 3 分钟内退出 | ≤ 20% | M1 / M2 |
| X-03 | 次日自愿再用 | 主动打开，自报 | ≥ 50% | M1 之后 |
| X-04 | 手臂疲劳 | 单手持机 3 分钟，1–5 分 | ≤ 3 | P0 / M2 |

| X-07 | 辨识度 | 不看标签、只看三视角截图，能否说出「天宫一号」 | ≥ 4/5 | M3.1 |
| X-08 | 细节可信 | "这个模型做得细不细"，1–5 分 | ≥ 3 | M3.1 |

体验指标不达阈值时，优先修体验，不推进内容。指标本身也是假设，P0 跑完后允许调整阈值，但必须写明调整理由。

## 12. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 平台 API 可用性误判（visionOS-only 当成 iOS 可用） | 中 | 高 | 已修正三处；新 API 实现前先写最小验证样例，用 SDK 头文件而非记忆确认可用性 |
| ~~房间尺度追踪漂移（B）~~ | — | — | **已作废 2026-11-07**：B 不再使用房间追踪（ADR-0004） |
| ~~基准机型虽有 LiDAR，遮挡与网格收益未达预期~~ | — | — | **已作废 2026-11-07**：虚拟视图没有遮挡与场景网格 |
| 2996 星实例性能不达标 | 中 | 高 | `MeshInstancesComponent` + 分桶合并 + 密度自动降级；M2 已实测 10 分钟 59.9fps 通过 |
| 真机专属项无法自动化测试（帧率、热、手感） | 高 | 中 | 门禁清单人工执行；纯逻辑抽成可单测的缝；几何预算用断言守住 |
| 非真实比例引发"不严谨"质疑 | 中 | 低 | 明确标注；信息卡给真实数值 |
| 史实/命名错误（天宫一号） | 低 | 高 | 统一称"目标飞行器/空间实验室"；史实条目附一手来源；禁词测试遍历全部可见文案 |
| 晕动与视觉疲劳 | 中 | 中 | 限制自动运动；提供暂停；不强制姿态模式 |
| **细节堆叠破坏剪影或拉低帧率（C）** | 中 | 中 | v0.10：四层分级 + 实体/三角形/draw call 预算封顶；**剪影优先于小件**——L0 不过不投 L1–L3；M3.1 门禁把预算与帧率一起测 |
| 文档完备掩盖体验未验证 | 高 | 高 | P0 原型先于工程化；每阶段附真机记录；体验指标进 DoD |
