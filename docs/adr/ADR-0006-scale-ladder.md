# ADR-0006：三个并列阶段改为「尺度阶梯」

- 状态：提议（2026-11-18；形态已定，技术细项见后续轮次）
- 修订：ADR-0002 的「三阶段独立交付」产品表述（工程上仍每层独立场景）
- 关联：`docs/1118.md`、PRD v0.11 §5、`GLOSSARY.md`

## 背景

A/B/C 三阶段各自过门禁、各自可演示，代价是三段之间没有因果关系：底部三个页签互不共享状态，用户看到的是三个并列 demo，而不是一件可以连续走完的事。

三座桥同时是断的：星图里没有太阳、月亮与行星（`Sources/Features/Sky` 零命中）；太阳系没有月球，行星位置来自硬编码 `startPhase` 而非真实日期；天宫场景里没有地球，只有一个抽象的 90 分钟轨道时钟。用户因此感受不到「光年 → 天文单位 → 公里 → 米」这条跨度，而这正是本产品唯一无法被截图替代的东西。

## 决策

D1 **四层**：星图 / 太阳系 / 地月系与近地轨道 / 天宫一号。地月系与近地轨道算**同一层的两个机位档**，不新增第五层。
D2 **删底部三页签**，竖向尺度阶梯成为唯一导航，保留上行返回路径。
D3 **下钻瞬间星图由姿态驱动切为手动机位**（`followsAttitude=false`，`.manual` 源），上行返回时恢复姿态，过渡提示一次。
D4 **真实比例不做交互开关**，做一帧叙事（约 0.6s），尺子同时显示「此刻行星直径 < 1 像素」，随后回到教学比例。
D5 封神星榜、一百单八将、封神行收进「文化」图层，默认关闭；首屏保留一次点击可达的入口。301 星官与星座连线**不**进该开关。
D6 **60 秒导览**随本轮首发、可重放，脚本与审核录屏共用一份主线。
D7 恒星距离**先只补 464 颗有专名的星**；全量距离等星表统一重建那次一起做。

## 理由

1. 三页签的根本问题不是命名，是并列：没有一层为下一层提供动机。四层各答一个问题，恰好互为伏笔。
2. 比例上四层各跨约三个数量级（1 AU 1e11 → 地月 1e8 → 近地 1e5 → 模型 1e1），缺了地月这级，太阳系到天宫是一次断崖。
3. 姿态驱动与自由机位是两种输入范式，无法补间。把「下钻即切手动」定成规则后，转场两端都退化成机位补间，唯一的未知只剩画面是否可信——可以交给原型去答。
4. 真比例开关没有正确的默认态：默认真比例则首屏看不见行星，默认教学比例则开关只是个会让人失望的按钮。一帧叙事把「空」变成一次陈述，而不是一个可反复进入的状态。
5. 文化内容在 `Sky` 的 7918 行里占比不小，抢的是主线注意力；但它仍是差异化卖点，所以降级为默认关闭的图层而非删除。
6. 尺子只需要亮星撑起「光年」这一段；为 464 颗星补距离即可，避免为此重开星表筛选口径的核对。

## 被否的方案

- **单一场景跨 26 个数量级**：浮点精度与 RealityKit 深度范围都撑不住，且每次进入需重建渲染树（FR-X-03'）。
- **保留三页签，阶梯只当尺子**：导航层的并列关系没变，根因未除。
- **真实比例做成开关**：见理由 4。
- **全量重建星表以补距离**：仓库内没有 HYG 原始数据，需外部取数，并会重开 2996 / 925 / 464 这组红线数字的核对。

## 后果

正面：一条可走完的主线；首次导览顺带解决「评审一分钟看不懂」的问题；四层共用一个星历，星图与太阳系的行星位置天然一致。

代价：导航层重写牵动 `ChromeLayout` / `ChromeState`、2 个 UI 测试文件、080/084 取证基线与 6 张已提交截图（需重采）；新增地月层场景与地球素材，须记入 `THIRD-PARTY.md`。

待定（下一轮）：尺子的度量语义、本轮范围切分、星历精度预算、帧率门禁口径、原型通过判据。
