# ADR-0004：B 阶段放弃房间追踪，改为「举机观星」

- 状态：已采纳（2026-11-07）
- 修订：ADR-0002 的 B 阶段设定、PRD §7.3
- 关联：ticket 022；`docs/assets/NASA-ASSETS.md`

## 背景

B 阶段原设计是「房间星海」：在以用户为中心、半径 3 米的房间空间里生成星点，走动时保持世界锁定，用姿态视锥选中星体。

A 阶段转虚拟后，重新审视这个设定发现一个物理矛盾。

## 决策

取消房间追踪。B 阶段改为**以设备姿态驱动的星图**：星空按 J2000 赤道坐标固定在无穷远，相机由 `CMDeviceMotion` 姿态驱动，用户举着手机转动，像透过舷窗看天。相机与房间都不参与。

## 理由

1. **视差悖论**：恒星在无穷远，走动 1 米产生的视差角为 0——"走到星星旁边"这个动作在画面上什么都不会发生。若把星点放在 3 米让视差可见，它们就不再像星，而像房间里漂浮的粒子。两种选择各错一半，没有中间态。
2. **真正改变视野的是转动，不是位移**。而转动只需要陀螺仪，不需要相机、平面或世界锚点。
3. **成本对比**：房间方案要付出漂移（实测锚点换绑一次跳 1.13 米）、暗光与白墙下的追踪丢失、持续相机与高亮的耗电发热、单手持机的手臂疲劳，以及"只能真机验证"的迭代代价；换来的却是上面那个不成立的体验。
4. **可用场景**：姿态方案在地铁、床上、户外、白天都能用；房间方案只在"有足够特征点、光线合适、愿意举着手机走动"时成立。

## 后果

正面：

- B 阶段零相机权限、零漂移、可模拟器验证（拖动模拟姿态）。
- 真实星表（HYG v4.1）替代随机星点，星座可核对，为后续「今夜星空」留了路。
- 与 A 阶段共用一套渲染与相机基础，代码复用高。

负面：

- 产品不再是"AR 应用"，AR 只剩「放进房间」这一个可选入口。
- 与 Sky Guide、Star Walk、Solar Walk 正面竞争，卖点变成内容与手感。
- 失去"被星海包围"的包围感；需要用近景尘埃层（几米内微光粒子）做补充，但那是效果，不是追踪。

## 赌注与止损

- 赌注：用户要的是**看清星空**，不是**在自己的房间里看星空**。
- 验证：B 首版跑 10 次记录，问"你会想举着手机走到窗外看吗"。
- Kill criteria：若 ≥ 6/10 的人第一反应是"能不能放进我房间"，则把「放进房间」提升为 B 的一等入口，并重新评估房间方案。

## 替代方案

- **房间星海（原方案）**：物理上不成立，且成本最高。否决。
- **抽象程序化星海**：便宜但没有"这是真的天空"的说服力，也做不了星座核对。否决（改为真实星表）。
- **纯虚拟飞行（相机在星海中穿行）**：观感像游戏，用户失去"我在看天"的定位感。保留为未来的"星际旅行"玩法，不作为 B 主路径。
