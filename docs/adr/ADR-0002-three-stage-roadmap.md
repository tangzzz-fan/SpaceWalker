# ADR-0002：产品按 A → B → C 三阶段串行演进

- 状态：已接受
- 日期：2026-11-07
- 决策者：Tang（方向拍板）、项目总监（拆分）
- 相关：PRD §4、§12

## 背景

产品目标是在真实空间里"漫步"浏览太阳系、星海与天宫一号任务。三块内容在交互复杂度、技术依赖与美术成本上差异很大，一次性并行实现会让风险叠加且无法定位问题来源。

## 决策

按 **A 桌面太阳系 → B 房间级星海 → C 天宫一号任务** 串行推进，每阶段独立过门禁后才进入下一阶段。

## 理由

1. 能力依赖是单向的：A 的平面锚定与实体操纵是 B 的前提；B 的实例化星点与姿态选中是 C 的前提。
2. 每阶段都能独立演示与验收，符合"节点提交 + 门禁"的工作方式。
3. 内容成本递增：A 用程序化几何验证玩法，避免在玩法未成立时投入 3D 资产。

## 后果

- C 阶段之前不引入外部 3D 资产管线与美术外包。
- 任一阶段门禁未过，不进入下一阶段；A 结束后允许重新评估 B 的形态（含推翻 B 的可能）。
- B 阶段的大范围追踪漂移若无法收敛，B 降级为"桌面尺度星海"，C 的场景尺度同步下调。

## 不采用

- **三阶段并行**：风险叠加，出现问题时无法判断是追踪、交互还是内容导致。
- **先做 C**：内容与美术成本最高，且依赖尚未验证的锚定与实例能力。
