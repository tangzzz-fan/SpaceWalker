## 0. 30 秒版

做一个**深空仪器**，不是太空游戏。

三个房间：**星图**（举机观星，3000 星 + 301 中国星官）、**太阳系**（点选 + 时间轴）、**天宫一号**（拆解 / 装配 / 对接 / 剖面 / 工程图 / 再入烧毁）。

现在的界面能用但丑：**顶部一张塞满小字和调试数据的卡片，底部一排无文字的图标**，三个模块长得一模一样。
需要的是：**一套统一的玻璃仪器语言 + 清晰的三模块导航 + 把调试信息全部赶出主界面**。

## 1. 产品是什么（设计师必须知道的边界）

| 项 | 事实 |
|---|---|
| 平台 | iOS 26+，仅 iPhone，竖屏 |
| 是否 AR | **不是**。不请求相机、不启动 ARKit。全部是虚拟相机 + 3D 场景 |
| 星图 | 2996 颗恒星（288 颗有专名可视星等 ≤4.5 可点选，以 PRD v0.6.1 为准；原 286 为笔误，2026-11-17 回写）、88 星座、301 中国星官；可切「今夜此刻」（按观测者位置与时间对齐真实天空） |
| 太阳系 | 太阳 + 8 行星，程序化几何，**比例做了非线性压缩**（必须标注） |
| 天宫一号 | 1:20 程序化几何；四模块可拆装；神舟对接判定（2 cm / 5°）；剖面（200° 舱壳）；工程图（四条尺寸标注）；「最后一圈」再入三拍 + 史实卡 |
| 内容红线 | 天宫一号是**目标飞行器 / 空间实验室**，界面**禁止出现「空间站」**；史实条目零错误 |
| 现实约束 | 60fps 是体验目标；数值验收判据以 `docs/PRD.md` NFR-01 为准（A/B 平均 ≥55fps、下限 ≥30fps；C 平均 ≥25fps、下限 ≥20fps，真机 30s 录屏 + 帧率统计，2026-11-16 按 PRD 回写）；无后处理、无粒子；所有素材自制或 NASA 公共域（不出现 NASA 标识） |

**用户是谁**：对中国航天有好感的普通 iPhone 用户，不是天文老手。他们会在夜里、床上、通勤时打开，单手操作，戴不戴眼镜都可能。

## 2. 现状诊断（附截图 `docs/design/current/`）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **调试数据显示在产品界面** | 天宫页顶部：`pick · tiangong.pick ok=4/5 occluded=leftWing->lab failed=none`；太阳系：`60fps · min 60 · 卡顿 0`；星图：`赤道坐标（未对齐今夜）` |
| 2 | **顶部卡片是一堵小字墙** | 三个模块都是同一个半透明圆角块，7–8 行 `.caption2`，没有主次；标题和读数一样大 |
| 3 | **底部是一排无文字图标** | 天宫 **9 个**图标、太阳系 5 个图标 + 时间轴、星图 **7 个**；无分组、无标签、功能不可猜；双圆环、飞船剪影这类图标语义不明 |
| 4 | **三模块没有导航模型** | 切模块靠底部第 2、3 个图标（太阳系 / 星图），天宫只能从太阳系的图标进；用户不知道自己在哪、还能去哪 |
| 5 | **满屏 `ultraThinMaterial` 胶囊** | 标签、卡片、工具栏全是同一种材质，没有层级；深空背景上糊成一片 |
| 6 | **常驻标签压住模型** | 天宫 5 个胶囊浮在舱段上，互相重叠、遮住细节（这也是 073 取证时被迫加 `NOLABEL` 开关的原因） |
| 7 | **信息重复** | 页面标题重复 App 名与模块名；同一句话在顶部卡片出现两次 |
| 8 | **无空态 / 无首次引导** | 第一次进来只有一个准星和一堆图标，不知道该干什么 |

## 3. 设计目标（可验收）

1. 新用户 **10 秒内**能说出「这是看星星 + 拆飞船的」。
2. 任何模块的**主操作 ≤ 1 次点击**可达；切换模块 ≤ 1 次点击。
3. 主界面**调试信息 0 处**（全部收进隐藏的诊断面板）。
4. 一级导航 ≤ 3 项，且**都带文字**。
5. 文字层级 ≤ 4 级，最小 11 pt；对比度 ≥ 4.5:1。
6. 主要操作落在屏幕下 40%，单手拇指可达。

---

## 4. 视觉方向：**深空仪器（Deep-space instrument）**

不是科幻游戏，也不是科普动画。参照物是**天文台控制台、星图仪、精密仪器的刻度盘**：黑、冷白、一点暖金；细线；读数等宽；没有一处多余的光。

**气质关键词**：克制、精密、安静、可信。
**反面参照（禁止）**：霓虹紫渐变、发光描边、玻璃拟态大圆角、游戏化 HUD、emoji、卡通星球、弹簧动画。

### 4.1 颜色（建议起点）

| 角色 | 值 | 用途 |
|---|---|---|
| 底 | `#05070D` | 全景背景（星空之上仍可见） |
| 层 1 | `#0C1018` | 面板 |
| 层 2 | `#141922` | 面板内的次级块 |
| 主文字 | `#F2F4F8` | 标题、数值 |
| 次文字 | `rgba(242,244,248,0.62)` | 说明 |
| 弱文字 | `rgba(242,244,248,0.38)` | 单位、出处 |
| 强调·暖金 | `#E8B15C` | 太阳、航天器、选中、主按钮 |
| 强调·冷青 | `#6FA8C8` | 星空层、连线、可交互提示 |
| 成功 | `#7FB08A` | 对接成功、装配到位 |
| 警示 | `#D96B5A` | 对接失败、越界 |

规则：**暖金只给「真实存在的东西」**（恒星、飞船、金牌操作）；冷青只给「信息层」（连线、网格、辅助线）。两者不同时出现在同一元素上。

### 4.2 字体

| 层级 | 字号/字重 | 用途 |
|---|---|---|
| 显示 | 28 / semibold（rounded 可选） | 模块名、天体名 |
| 标题 | 22 / semibold | 卡片主标题 |
| 正文 | 15 / regular | 说明、史实 |
| 注释 | 12 / regular | 单位、出处 |
| 读数 | 15 / medium + `monospacedDigit` | 时间、距离、角度、帧率 |

**只有读数用等宽数字**。现在满屏等宽小字是噪音来源之一。

### 4.3 形状与材质

- 面板：圆角 **14**，填充 `rgba(10,14,20,0.72)` + `.background(.ultraThinMaterial)` 叠加，**1 px** 描边 `rgba(255,255,255,0.10)`。
- 不用投影；靠描边与填充区分层级。
- 按钮：主按钮实心暖金（黑字），次按钮描边（白 12%），图标按钮一律 **28×28 触区 + 44×44 响应区**。
- 禁止：同屏超过 **2 个**半透明面板；禁止胶囊套胶囊。

### 4.4 图标

- 统一 SF Symbols，`weight: .regular`，`size: 17`；**同一位置不得混用 filled 与 outline**。
- 现有语义不明的图标必须换掉或加文字（`(p)`、双圆环、乌龟/兔子）。

### 4.5 动效（只允许三类）

| 类型 | 时长 | 曲线 | 场景 |
|---|---|---|---|
| 相机 | 450 ms | easeInOut | 切换预设视角、进/出剖面 |
| 面板 | 280 ms | easeOut | 卡片出入、任务条展开 |
| 状态 | 150 ms | linear | 选中、开关、颜色变化 |

**禁止**弹簧、弹跳、呼吸光、循环动画（轨道时钟驱动的天体运动除外，那是内容本身）。

## 5. 信息架构与导航

### 5.1 顶层

```
星槎
├── 星图        ← 默认落地（最强的钩子，且零学习成本）
├── 太阳系
└── 天宫一号
（诊断 · 素材来源 · 关于 —— 收在「…」里，不做一级入口）
```

**底部一级导航：3 个 tab，图标 + 文字**（星图 / 太阳系 / 天宫一号）。当前 tab 用暖金点 + 文字提亮，不用填充块。

> 现在默认落地是太阳系，建议改为星图：举起手机就能看到星空，是最快的一次「哦」。

### 5.2 每个模块的骨架

```
┌─────────────────────────────┐
│ 状态条（44pt，只读）          │  模块名 · 一句状态 · 右侧仅「…」
├─────────────────────────────┤
│                             │
│         3D 场景              │  全屏铺满，控件浮在上层
│                             │
│  （选中时才出现的信息卡）      │  从底部升起，可下滑收起
├─────────────────────────────┤
│ 主操作（1 个，暖金实心）       │  随模块变化，落在屏幕下 40%
│ 上下文控件（≤3 个，带文字）    │  随模块变化
├─────────────────────────────┤
│ tab: 星图 · 太阳系 · 天宫     │
└─────────────────────────────┘
```

- **状态条**替代现在的「小字墙」，且**只读**：一行标题 + 一行状态，最多两行，不放主操作。
- **唯一主操作**固定在底部区最上层，暖金实心，随模块变化（星图「找星」/ 太阳系「聚焦」/ 天宫「开始拆解」等），不重复出现在状态条或信息卡里。v1.1 裁决：设计稿 v1 的「顶栏主操作」已否决。
- **次级操作**进「…」菜单（24 pt 图标，与状态条同排）。
- **信息卡**只在有选中时出现，高度 ≤ 屏高 32%，可下滑关闭，且不遮挡底部主操作。

## 7. 关键交互

| 手势 | 星图 | 太阳系 | 天宫 |
|---|---|---|---|
| 单指拖动 | 环视（手动模式） | 旋转相机 | 旋转相机 / 拖已分离模块 |
| 双指捏合 | 缩放视场 | 缩放 | 推拉距离 / 对接推进 |
| 双指旋转 | — | — | 对接时调飞船姿态 |
| 轻点 | 选中星 | 选中天体 | 选中模块 |
| 长按 | — | 显示天体名提示 | 显示模块名提示（替代常驻标签） |

**冲突规则**：一次手势只归属一个对象，按下时判定、中途不变（现状已如此，设计稿需体现反馈差异：拖模块时模块跟手，拖相机时模型不动）。

## 8. 空态与异常

| 场景 | 要求 |
|---|---|
| 首次进入 | 一条 3 秒的提示（「举起手机，星空会跟着你转」），不做出多页教程 |
| 星表未就绪 | 骨架星空 + 一行「正在载入星表」，不要转圈遮罩 |
| 姿态不可用 | 右下角状态 chip 变灰 + 一次 toast「已切到手动拖动」 |
| 定位被拒 | 「今夜」改为手动选城市，不弹系统权限二次请求 |
| 对接失败 | 卡片顶部红色细条 + 一句原因（四类之一）+ `重试`，不用弹窗 |
| 再入彩蛋未解锁 | 按钮置灰 + 一行 11pt 说明「完成三步任务并看过史实后解锁」，点击时提示，不隐藏 |

## 9. 硬约束（设计不得违反）

1. **不引入 AR / 相机**：不设计任何「扫描房间」「放置到桌面」入口。
2. **不显示调试数据**：fps、pick 自检、坐标系统状态一律进诊断面板（长按版本号 3 秒进入）。
3. **史实零错误**：不出现「空间站」；日期只用 2011-09-29 / 2016-03-16 / 2018-04-02。
4. **不新增几何与特效**：不加粒子、不加后处理、不加发光描边；模型由代码生成，设计稿不得改动外形比例。
5. **性能**：任何常驻动画都算预算；允许的常驻动画只有轨道运动本身。
6. **单手可用**：主操作在屏幕下 40%；顶部只放只读信息与「…」。（v1.1 裁决：本条为硬约束，设计稿 v1 的「顶栏主操作」偏差已否决。）
7. **不横屏**，不做 iPad 版式（1.0）。

## 12. 可直接投喂 open-design 的简报

```
为 iOS 应用「星槎」设计一套深色 UI，气质 = 深空仪器（克制、精密、安静），
反面 = 霓虹渐变 / 发光描边 / 游戏化 HUD / 卡通星球。
```
