# 月相网格 terminatorScale 符号反了，被自己的错误断言带偏成"编译器/ABI 问题"

日期：2026-11-19 · 场景：089 星图桥，MoonPhaseGlyph.mesh 月相网格测试失败

## 前因

089 给星图加月球，`MoonPhaseGlyph.mesh` 用「亮缘半圆 + 椭圆明暗界线」构造亮面网格。
测试 `testMoonGlyphTerminatorFollowsPhase` 失败：新月期望无亮面、实测亮面宽度=2。
第一版实现 `terminatorScale = 1 - 2*lit` 本来是对的；我误判断言失败是"画到了背光侧"，
把公式改成 `2*lit - 1`（方向恰好反了），同时新断言用「亮缘到界线的 x 距离」度量亮面宽度——
这个度量本身也是错的（新月时两者在圆盘两端，距离=直径 2 是正确几何）。
两个错误叠加后，失败值（新月面积≈π、满月面积≈0）看起来像"phase 参数在函数入口被篡改"，
于是我转向怀疑工具链。

## 本质

**一个符号错误（`2*lit-1` 应为 `1-2*lit`），不是编译器、ABI、缓存或模拟器问题。**
几何：界线椭圆 x = cos(a)·(1−2·lit)。lit=0 时界线与亮缘重合→面积 0（新月）；
lit=1 时界线镜像到对侧→整个圆盘（满月）。符号反过来则新月=满盘、满月=空盘，
与运行时观测完全一致，能解释全部失败值。

## 证据

失败输出（符号错误版）：

```
error: ("3.1350057") is not equal to ("0.0") +/- ("0.001") - 新月无亮面
error: ("0.0") is not equal to ("3.1415925") +/- ("0.02") - 满月整个圆面
error: ("2.351254") is not less than ("0.0") - 蛾眉月亮面小于半圆
```

独立 Python 复算同一算法（不经过 Swift 工具链），失败值逐位吻合：

```
$ python3 -c '... s=2*frac-1 ...'   # 错误符号
0 → 3.135005   0.25 → 2.351254   1 → 0.0
$ python3 -c '... s=1-2*frac ...'   # 正确符号
0 → 0.0   0.25 → 0.783751(期望 0.785398)   1 → 3.135005(期望 3.141593，28 段内接多边形误差)
```

修复一行后：`SkyEphemerisTests` 11/11 通过，全量 486 tests 0 failures。

## 如果重来

1. **先怀疑自己的断言和公式，再怀疑工具链。** 失败第一步应做独立复算（Python 十行即可），
   而不是 clean/换模拟器/反汇编。本次若先复算，5 分钟定位。
2. 「函数内 print 正确、返回后错误」的观测当时被我解读为 ABI 问题——实际上函数内探针
   打印的是中间量，断言度量的是另一个几何量，两者根本不可比。对照实验必须度量同一量。
3. 反汇编读 Float 参数传递（d0/s0 寄存器）极易误读，静态分析超过 3 轮无进展就该切换
   判别实验（本次最后的显式 segments 实验方向是对的，但更早就该做独立复算）。
