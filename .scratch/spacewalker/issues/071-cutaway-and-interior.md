## 背景

博物馆的做法是 1:1 进舱（内蒙古科技馆），我们做不到 1:1，但可以"开一半让你看"。
它是目前唯一能把「这是天宫一号」升级成「航天员在里面怎么生活」的手段。

RealityKit 没有裁剪平面，所以这不是"切开"，是**只造 200° 的舱壳**、缺口朝相机。

## 范围

- 「剖面」模式：实验舱外壳换成约 200° 的舱壳（缺口朝相机方向，随相机 yaw 更新缺口朝向）。
- 内景三处示意 + 名称：睡眠区、健身区、设备机柜；非密封后锥段补遥感设备示意。
- 转移通道：沿对接轴在舱内画出 Ø0.8 m 的通道，与 FR-C-01 的 0.8 m 同源。
- 点对接口 → 相机沿轴推进到舱内近距（复用 `TiangongRig`：`distance` 收近 + 位置沿 +Z 平移），1.2s 内完成。
- 默认关闭；进入/退出各一次交互。

## 验收标准

- [ ] 剖面下三处内部分区可辨认、有名称（VoiceOver 也能读）。
- [ ] 缺口朝向随相机 yaw 更新，任何角度都不会看到"背面漏光"。
- [ ] 推进动画 ≤ 1.2s；退出后恢复完整外壳与默认相机角度，不残留。
- [ ] 剖面模式下拆解/装配/拾取仍可用（`verifyPicking` 不回退）。
- [ ] 几何回到预算内：实体 ≤ 60、三角形 ≤ 20k（半舱壳替换整壳，净增应 < 5k）。
- [ ] **默认视图的截图与 068 基线逐像素比对差异为 0**——模式默认关闭，不许改变基线。

## 测试缝

缺口角度、通道直径、内景子件数都是几何断言。
"默认关闭不改变基线"用截图比对（既有手法：固定点构建 → 截图 → PIL 比对）。

## 备注

- 半舱壳的端面要封口，否则从缺口看进去会看到零厚度的壳片（这是最容易翻车的地方）。
- 内景只做"看得懂"，不做"看得真"。软装（睡袋、跑台细节）一律用几何示意，不引图片。
- 这票吃几何预算，必须排在 068 之后；否则 M3.1 的基线会被它改掉。

## 实现记录

**做成的**：`TiangongMesh.arcShell` 生成 200° 圆弧壳体（外壁 + 内壁 + 两端封口 + 两条侧壁，含厚度），
剖面模式下用它替换整舱圆柱；舱内放转移通道（Ø0.8 m）、4 个机柜、睡眠区、健身区，
全部挂在 `lab-interior` 下、默认禁用。缺口朝向按相机在 XY 平面的投影实时旋转。

灰度：舱壁 0.78 无光照，内景 0.44–0.92 自发光。**内景必须自发光**——舱壁挡住太阳后舱内没有任何光源，
纯 PBR 一律发黑。

**三个真 bug，一个比一个贵**：

1. **模式切换早于场景构建**（与 072 同一类）。`cutawayMode` 标记为真、材质没换。
   这次直接抽了 `applyCutawayState()`，在 `build()` 末尾补调。**同一类坑在一张票里出现两次，
   说明"标志位"与"渲染树"的时序没有统一约束，后续模式（073）要一开始就按这个写法。**

2. **缺口朝向反了 180°**。`atan2(offset.y, offset.x)` 把圆弧的**中心**（有壁的那一半）对准了相机，
   缺口自然背过去。症状极具误导性：舱内一片黑、自发光无效、点光无效、翻转内壁法线无效——
   看起来像光照问题，实际是**我们从开口看过去，那一侧本来就没有壁**。
   决定性证据是：那片黑里**能看见星星**（背景透进来了）。诊断为光照花了 6 轮构建。

3. **相机用了局部坐标**。`labCylinderOffset` 是舱内局部偏移，直接当世界坐标用，相机跑进资源舱。

**取消「推进进舱」**：1:20 下舱内直径 16 cm，rig 绕整机中心转，拉近必然把舱段切出画面；
试过自定义机位，进去后相机贴在箱体上、画面全是面。**这个尺度上没有可用实现，不做。**
PRD FR-C-09 已改，写清理由。剖开本身已经满足"看见内部"。

**验证**：348 项测试 0 失败（新增 3 项：壳体与内景互换、内景命名齐全、默认视图模型数守预算）。
截图 `docs/gates/M3.1/071-cutaway.png`。

**顺带修正一个度量**：`modelEntityCount` 原来把禁用实体也算进 draw call 预算。
改成只数 `isEnabled` 的——禁用实体不进渲染，这才是 draw call 的代理指标。
