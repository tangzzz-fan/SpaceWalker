# 040 星群：大三角与春季大弧线，并把天区判定收成一套

## 一、为什么做星群

星座连线是骨架，但它假设用户已经知道自己看的是哪个星座。新手真正缺的是「先找到一个大形状，再从形状走到星座」这一步。星群就是这一步的抓手：冬季大三角一颗星都不用认，看见三颗最亮的连成三角形，大犬、小犬、猎户就都在旁边。

顺带把 039 的遗留钉死：小犬座只有 Procyon 与 Gomeisa 两颗星，**画不出面**，它的「轮廓」与它的连线是同一根线段，补了不增加任何信息。所以 30/31 不是没做完，是天花板；小犬座改用冬季大三角接进这套形状里——三角形的另外两个顶点就是天狼与参宿四。

三条数据：

| 星群 | 锚星 | 边（度） | 虚线段 | 闭合 |
|---|---|---|---|---|
| 冬季大三角 | Sirius / Procyon / Betelgeuse | 25.7 · 26.0 · 27.1 | 31 | 是 |
| 夏季大三角 | Vega / Deneb / Altair | 23.8 · 38.0 · 34.2 | 38 | 是 |
| 春季大弧线 | Alioth / Mizar / Alkaid / Arcturus / Spica | 4.4 · 6.7 · 30.7 · 32.8 | 29 | 否（折线） |

## 二、画法：为什么是虚线

星群和星座连线挤在同一片天上，如果都画实线，用户分不清「这是星座的骨架」还是「这是我该顺着找的路标」。所以星群画虚线：段长 1.3°、空隙占周期 45%，向远处一指就能看出这是参考线而不是成员连线。

| 参数 | 值 | 理由 |
|---|---|---|
| 段长 | 1.3° | 一臂远处约两根手指宽，看得见又不会连成实线 |
| 空隙 | 周期的 45% | 低于 30% 看起来像实线，高于 60% 会断成点 |
| 两端让位 | 各 1.0° | 最亮星（-1.5 等）在半径 50 的天球上视半径 ≈ 0.62/50 rad ≈ 0.71°，让 1° 才不压星点 |
| 天球半径 | 49.0 | 星官 49.4、星官高亮 49.2 在前；星座连线 50、星点 50 在后 |
| 管径 / 色 | 0.018 / (0.80, 0.66, 0.98) × 0.60 | 比星官（0.026、琥珀）细，色相偏紫，三层叠在一起也不混 |

**第一版没让位，紫线直接压进了天狼的星面**（放大到 3 倍能看见一条紫线切过白色圆盘）。加 inset 后虚线的端点退到星点之外，读起来是「这条线指的是那颗星」，而不是「这颗星上长了条线」。

叠层实拍：`sky-pattern-layers.png`（星座连线 + 轮廓色块 + 星官 + 星群同时开，无 z-fighting）。

## 三、判定：闭合才有内部

`ConstellationOutlineShape` 改名为 `OutlineShape`，字段 `abbreviation` 改成 `key`——它现在同时服务星座（缩写如 `Ori`）和星群（id 如 `winter-triangle`）。切平面投影 + 射线法一行没改，直接复用。

折线星群（春季大弧线）没有内部，`SkyPatternGeometry.ring` 直接返回 nil，不参与「落在星群里」的判定——指着弧线本身也不会弹卡，这是对的：一条线不该有面积。

点环判定的优先级：

```
星体 > 星座轮廓 > 星群
```

指着猎户座腹地时说猎户座，不会因为整片区域在冬季大三角里而被大三角抢答。只有落在没有轮廓的天区（麒麟、天兔这些），星群才有资格说话。

## 四、顶栏与标识卡收成一套

039 的遗留是「顶栏用最近星、点环用轮廓，两套判定」。顶栏问的也是「你在哪个星座」，两套算法在同一问题上可以给出不同答案，这本身就是债。

新实现合成一个函数 `SkyScene.currentRegion()`，优先级与点环识别一致：

| 档 | 判定 | 距离 |
|---|---|---|
| 1 | 落在星座轮廓内 | 0 |
| 2 | 落在闭合星群内 | 0 |
| 3 | 最近成员星 | 实际角距 |

**中途试过加 15° 门槛，实测把它否掉了。** 原本的理由是「指着空天区不该报一个几十度外的星座」。但 6 等星表 2996 颗把整个天球盖满了：均匀撒 4000 个方向，到最近成员星最远只有 6.9°（p50 1.8°、p99 4.9°）——15° 的门槛一次都不会触发，留着只是假装严谨。门槛撤掉，换成一条测试把「盖满全天」这个前提钉住：星表哪天缩水到盖不住，测试会红。

真正修掉的是**两张嘴**。第一版截完图才发现顶栏写「麒麟座」、底栏卡片写「冬季大三角」：前者是最近星兜底，后者是星群判定，各自都对，放在同一屏里却像 bug。现在顶栏与卡片走同一条链，截图里两处都叫冬季大三角。

顶栏链接的动作也跟着分流：星座进 88 星座来头面板，星群直接把标识卡钉在屏幕上。

## 五、四个踩到的坑

**1. 锚星顺序写反了。** 春季大弧线第一版写成 `Alkaid → Mizar → Alioth → Arcturus`，看起来是「从斗柄末端往回走再折向大角」，画出一个人字形。单测报：`在 Alioth 处折返，入向与出向夹角 50.5°`。正确的是 `Alioth → Mizar → Alkaid → Arcturus → Spica`，三处转角分别 38.4° / 25.4° / 45.0°。

**2. 转角断言写反了。** 第一版断言 `180 - turn > 120`，等于要求路径折返，结果把正确的顺序也判失败。正确的断言是比较 `angle(中间星→前一星, 中间星→后一星)` 与 120°：路径平顺时这个角接近 180°。

**3. 段数不能当断言。** 折线 29 段比三角形 31 段少，所以「折线段数更多」是错的。改成「每条边至少画出一段」——它才真正对应「有没有边被吃光」。

**4. 竖屏装不下夏季大三角。** 水平视场只有三十几度，38° 的那条边出画，得转一下手机。这不是 bug（看天本来就要转），但意味着星群的「中心对准」只能保证大致落在视野里，截图里 冬季大三角 刚好装下、夏季大三角 装不下。

## 七、遗留

- 星群只有一层统一配色，没按季节或类型区分；三条已经够用，再加就该考虑分组开关。
- 冬季六边形（天狼—南河三—北河三—五车二—毕宿五—参宿七）没做：六条边会盖住太多星座，先看三条用一段时间。
- 星群不进「今夜导览」的候选项——导览仍以星座和星官为单位，因为星群跨星座，塞进「方位 + 高度」的措辞里会乱。
- 顶栏只显示一个名字。落在冬季大三角里、同时又够得着麒麟座时，麒麟座会被星群盖住；两级信息挤一行会读成一串，暂不合并。
