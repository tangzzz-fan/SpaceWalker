## 背景

062 当年否决"线框表达"，是因为它在评估它能不能**替代**实体表达——结论是不能，太抽象。
但它**作为附加模式**价值完全不同：和"史实/参数"的叙事天然契合，也是这个产品区别于
"又一个太空 CG"的地方。

工作量几乎全在 UI（标注布局），不在 3D。

## 范围

- 「工程图」模式：几何换 unlit 材质（深底 + 浅色线框/淡色实体），关掉方向光与 IBL。
- 屏幕空间标注四条：全长 10.4 m、最大直径 3.35 m、翼展 18.405 m、转移通道 0.8 m。
  数值从 `TiangongModel` 取，**不许另写字面量**。
- 正 / 侧 / 俯三视图快捷切换（固定 rig 角度 + 正交感：拉远 + 小 FOV）。
- 默认关闭。

## 验收标准

- [ ] 四条标注数值与 `TiangongModel` 常量逐位一致（用测试断言，不靠肉眼）。
- [ ] 标注两两不重叠、不出屏；任意三视图切换后仍然不重叠。
- [ ] 模式切换 ≤ 0.3s，不触发整树重建（`rebuild()` 只在路由切换时调用）。
- [ ] 关闭模式后回到默认视图，光照恢复。
- [ ] 默认视图截图与 068 基线差异为 0。

## 测试缝

标注锚点 = 几何端点的屏幕投影，可对"投影是否在屏幕内""两标注矩形是否相交"做纯函数断言。
这是少见的"UI 布局可单测"场景，值得做。

## 备注

- 三视图用"拉远 + 小 FOV"模拟正交，不用真正交相机——RealityKit 的虚拟相机不好切投影矩阵，
  而 1:20 的尺度下透视误差在标注精度内可接受。这一点要写在代码注释里说明是近似。
- 标注不要用 3D 文字，用 SwiftUI 覆盖层投影定位，与现有标签层同一套机制（但要解决 062 的白屏坑：
  锚点不进 `@State`，用 `TimelineView` 自刷新）。

## 实现记录

RealityKit 没有线框渲染，所以取 FR-C-10 允许的另一半：**无光照淡色实体 + 屏幕空间标注**。

- `TiangongScene.setDrawingMode` 关掉三盏灯，把每个零件的材质换成 `UnlitMaterial`。
  灰度按构件分配：太阳翼 0.46、资源舱 0.70、实验舱 0.92、神舟 0.80、硬件 0.60。
  **不分灰度的话整机会糊成一个剪影**——这是第一版实际踩到的。
- 四条标注（全长 10.4 / 最大直径 3.35 / 翼展 18.405 / 转移通道 0.8）全部由 `TiangongModel` 推导，
  界面零字面量；`TiangongDimension` 是纯值，可单测。
- 标注位置用投影点 + 每条的固定偏移，再按屏宽钳到 78…width−78，避免被切。
- 三个视图预设（正/侧/俯）改 rig 的 yaw/pitch/distance，再 `scene.apply(rig:)`。

**一个真 bug**：`toggleDrawingMode` 在 `.task` 里调，那时 `RealityView` 的 make 还没跑、`moduleNodes` 是空的，
于是模式标记为真但材质没换——界面出现了标注、模型还是带光照的。修法是把应用逻辑抽成
`applyDrawingMode()`，在 `build()` 末尾再调一次。**"状态对了但渲染没跟上"这类问题，只看截图会误判成没生效。**

**验证**：343 项测试 0 失败（新增 4 项：标注与常量同源、四条锚点互异、切模式不换 root、三视图预设改 rig）。
截图 `docs/gates/M3.1/072-drawing-mode.png`：四标签完整在屏内、无重叠、虚线可见。

**遗留**：
1. 默认视图与 M3.1 基线的逐像素比对没做——069 的轨道时钟改了默认光照，基线本身要重拍，
   等 068 盲测结论定了一起做。
2. 退出模式后的材质恢复只有标志位断言，没有视觉验证（无头环境点不到按钮）。风险低：
   `baseMaterials` 按 ObjectIdentifier 存原始材质，`rebuild()` 会清空。
