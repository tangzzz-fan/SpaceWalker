## 背景

把拆解、装配、对接串成一条可理解的任务链，并在失败时给出可行动的信息。
任务卡纯本地、可重玩、保留已解锁的史实卡片。

## 范围

- 三个任务按顺序解锁：拆解 → 装配 → 对接。
- 任务卡：目标、当前步骤、进度、失败原因、重试入口。
- 失败原因直接引用 017/018 判定输出的文案，不另造第二套说法。
- 重玩：重置任务到初始状态，保留已解锁的史实卡片。
- 任务状态机是纯值，放在会话里，View 只渲染。

## 验收标准

- [ ] 三个任务按顺序解锁，未完成前不进入下一任务。
- [ ] 每一步有明确状态：未开始 / 进行中 / 完成 / 失败。
- [ ] 失败原因与 017/018 的判定输出逐字一致（同一条测试断言两处字符串相等）。
- [ ] 重玩 3 次无状态残留：模块位姿、选中、计时、进度全部归零。
- [ ] 重玩后史实卡片仍可查看（解锁状态不清）。
- [ ] 全程无网络依赖，飞行模式可完成整个任务链。

## 测试缝

- 状态机：输入事件序列 → 输出任务与步骤状态（纯函数）。
- 重玩：输入已完成状态 → 输出初始状态 + 保留的解锁集合（纯函数）。
- 文案同源：失败原因只有一个来源，两处渲染取同一个值。

## 备注

- 任务数量、解锁顺序、文案均可调整，改的是数据不是结构。
- 任务卡视觉沿用 A 阶段信息卡的语言，不新造一套。
- 真机验收由 020 承接。
