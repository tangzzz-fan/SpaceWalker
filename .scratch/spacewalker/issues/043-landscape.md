# 043 横屏：排版、保尺度、以及拖动了半年的滚转 bug

- 日期：2026-11-07
- 状态：完成
- 关联：042（88 座骨架与插画）、040（星群与天区判定）

## 一、为什么做横屏

竖屏水平视场只有三十几度，人马座跨 24°×28.5°、天鹅十字 30°，一次装不下。前面试过拉远到 95°，但那是「把整片天缩小」——线宽也跟着细回去，等于把 043 之前的加粗成果又还回去。

横屏是另一条路：同样 60° 的竖直视场，横过来水平就有 90°+。

## 二、先否掉自己的第一版：相机不该滚

第一版给相机加了绕视线轴的滚转补偿：竖屏 0°、左横屏 +90°、右横屏 −90°，理由是「屏幕转了，世界正上方得跟着转回来」。

写完先跑模拟器，日志里 `sky.roll up=0.00,1.00`——世界正上方指向屏幕下方。查下去才发现前提就错了：

- 相机（identity）挂在 content 根上，星空的姿态写在 `root.orientation = world⁻¹` 上，也就是**星星被摆到机身坐标系里**；
- 机身转 90°，星空跟着转 90°，屏幕上的地平线也就转 90°——**这正是 AR 该有的行为**，和透过手机看到的真实天空完全一致；
- 如果再滚相机把它「扶正」，叠加真实天空时反而会歪 90°。

所以第一版整个删掉，一行不留。横屏只改排版，不动相机。

**教训**：AR 叠加类应用里，「顺手把画面摆正」几乎一定是错的。判断标准不是截图好看，而是举起来对不对得上。

## 三、排版

| | 竖屏 | 横屏 |
|---|---|---|
| 顶栏 | 左上整块（标题、坐标、状态、时间滑块、当前天区、朝北按钮） | 压成一行胶囊（标题、坐标、当前天区 + 滑块），朝北按钮降为图标 |
| 卡片 | 底部依次堆叠 | 右侧 340pt 竖栏，可滚动；中间视场留空 |
| 底栏 | 通栏胶囊 | 按内容收紧、居中 |
| 性能读数 | 右上 | 顶栏下方，左对齐 |

判定用 `verticalSizeClass == .compact`（iPhone 横屏即 compact，iPad 横屏是 regular，仍走竖屏排版——它有地方）。

## 四、转屏保尺度

一开始只改排版，转过去后同一片天缩成一半——竖直 60° 摊到 402pt 上，每点对应的角度只有竖屏的一半。

改成转屏时按高度比例缩视场：`fov *= newHeight / oldHeight`，竖屏 60° → 横屏 31°，每点角度不变，星座看起来一样大，只是两边更空。捏合基准 `zoomBase` 同步，否则下次捏合会跳一下。

只在**长短边互换**时触发；分屏、来电横幅这类同方向的高度变化不动视场（否则每变一次缩一点）。

代价：31° 竖直装不下人马座 38° 的对角。这不是 bug——**「看全」靠捏合，不靠转屏**。竖屏 33°×60° 反而装得下它，因为它立着。这条结论和 043 之前的说法相反，以数据为准。

## 五、真正的 bug：拖动时整片天会滚

做 `aim` 的交接时顺手验了一下「世界正上方在相机坐标里应当只有 +Y 分量」，结果不是。

根因在 `SkyRig.orientation`：`Ry(yaw) · Rx(pitch)` 描述的是**相机**朝向，却被直接赋给了星空（`root.orientation`）。星空要转相机的逆，`Rx(−pitch) · Ry(−yaw)`。

实测滚转角：

| yaw | pitch | 滚转 |
|---|---|---|
| 0° | 30° | 0° |
| 90° | 30° | 0° |
| −30° | 45° | **58°** |
| 60° | −60° | **41°** |
| 170° | −20° | 7° |

也就是说：先抬头 45°，再横着拖一下，整片天会斜 58°。没有地平线参照，肉眼很难发现，但它一直在。

改法：`orientation` 取逆，同时把 `drag` 的两个符号翻过来（`yaw += dx`、`pitch += dy`），手感不变——`testDragRightMovesTheViewLeft` 与 `testDragDownLiftsView` 钉住这两个方向。

## 六、aim 顺手修的三件事

1. **不再用最短弧**：`simd_quatf(from:to:)` 的滚转是任意的，定位到星座后整片天歪着出现。改成 yaw/pitch 两轴构造，滚转恒为 0（`testAimCentersTheDirectionAndLeavesNoRoll`）。
2. **交出 rig**：`aim` 返回等价的 `SkyRig`，调用方同步给 `@State rig`。否则一捏合 `releaseAim()`，`apply(rig:)` 立刻把画面拽回旧角度——这一条是先在截图上撞见的：捏合之后高亮整块跑出画面。
3. **取最小覆盖圆圆心**：人马座骨架质心离包围中心 2.4°，定位过去总有一头出画。改成两两中点的最小覆盖圆（25 颗星 300 次循环，启动时算），`testEnclosingCenterBeatsCentroidOnAsymmetricShapes` 钉住「必须比质心更居中」。

## 七、手势

- 双指捏合改视场（16–95°），双击复位 60°。
- **捏合期间要挡掉拖动**：两指落下时 `DragGesture` 也在跑，会把两指的位移当成平移，缩放顺带把天空推走。用 `isPinching` 挡，并在捏合第一帧把 `rig` 回滚到手势前的快照。
- 模拟器验证：`app.pinch(withScale: 2.0)` 能触发，日志 `sky.fov 29.5 → 20.2 → 17.5 → 16.0`（下限夹住）；截图里人马座仍以准星为中心放大，没有平移。`withScale: 0.55` 这一侧在模拟器上识别不出来，别拿它当断言。

## 八、验收

新增 UI 测试 target 与 `SkyCheck` scheme（`xcodebuild -scheme SkyCheck test`）：`XCUIDevice` 真把设备转到左右横屏，`XCUIScreen` 截图并按 `imageOrientation` 烘正，断言 `星图` 与 `人马座` 都还在。

## 九、遗留

- 横屏默认 31° 竖直装不下人马座 38°，要捏一下。若日后证明这个尺度太紧，可给横屏一个 1.2–1.3 的补偿系数，代价是转屏时轻微缩水。
- 捏合缩小（手指并拢）在模拟器上不触发 MagnifyGesture，只能真机验。
- 拖动到 ±77° 就顶住，登不了顶；`SkyRig.pitchRange` 这是老限制，与横屏无关。
