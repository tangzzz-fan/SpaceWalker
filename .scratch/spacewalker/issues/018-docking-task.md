## 背景

C 阶段的核心玩法：控制神舟飞船靠近天宫一号对接口，在容差内完成对接。
这是"看得懂、做得到、失败得起"的任务，也是 M3 三条 KR 里唯一靠手感成立的一条。

## 范围

- 六自由度输入：单指拖动 = 横/纵向平移；双指捏合 = 轴向推进/后退；
  双指旋转 = 俯仰/偏航微调；长按 200ms = 粗调/精调切换。
- 设备姿态微调是 P1：有陀螺仪才给，没有就隐藏（同 B 阶段 `canFollowAttitude` 的处理）。
- 成功条件（展示尺度，需持续 1 秒）：接近速度 ≤ 0.02m/s、轴向偏差 ≤ 2cm、
  姿态偏差 ≤ 5°、角速度 ≤ 5°/s。
- 四类失败：过快、偏角过大、撞偏（接触时超差）、超时（90 秒）。
- 失败后可一键重试，不退出场景。

## 验收标准

- [x] 三个自由度接入手势：拖动平移 x/y、捏合推进 z；粗调/精调切换（灵敏度 1 : 0.25）有按钮反馈。
- [ ] 俯仰/偏航两个姿态自由度**未接**：手势与设备姿态都没做（见遗留）。
- [x] 成功路径可复现：判定连跑 21 次结果一致（`testDeterministic`）。
- [x] 四类失败均可触发：`tooFast` / `offAxis` / `tooSteep` / `timeout`，文案单一来源且互不重复。
- [x] 容差边界：轴向 0.99/1.01、横向 0.99/1.01 各两条（`testToleranceBoundary`）。
- [x] 失败后「重试」按钮回到初始位姿，计时与保持时间归零。
- [x] 判定与输入映射都是纯函数，不 import RealityKit。

## 实现记录

- `TiangongDocking.judge` 的判定顺序就是玩家能感知的顺序：超时 → 还没靠近 → 接触瞬间查速度 → 横向 → 角度。
- 保持时间由 `delta` 累加，0.1s 步长下 10 帧即 1 秒。
- 速度取相邻两帧位移 / delta。0.1s 的量化会让「猛拖一下」直接判过快，符合直觉。
- 进入对接前强制复位所有分离模块，避免「半拆状态下去对接」这种说不清的场面。
- `SPACEWALKER_TG_DOCK=1` 启动即进对接，供无头截图。

## 遗留

- **俯仰/偏航未接**：`Input.angleDegrees` 已支持判定，但没有任何输入能改变它，所以 `tooSteep` 在 UI 上不可达（测试覆盖）。
  补齐需要：双指旋转手势 + 设备姿态微调 + 神舟实体的姿态反馈。
- **撞偏语义**：现在 `offAxis` 就是「横向偏差超容差」，与「接触时超差」是同一件事，没有单独的撞偏速度门槛。
- 六自由度齐了之后要重跑 020 的录屏。

## 测试缝

- 对接判定：输入相对位姿/速度/角速度/持续时间 → 输出成功或失败原因（纯函数）。
- 输入映射：输入手势增量 + 粗调精调模式 → 输出六自由度增量（纯函数）。
- 容差边界：参数化测试，阈值两侧各取点。

## 备注

- 0.02m/s、2cm、5°、5°/s、90s 均为默认值，真机试玩后可调常量，判定结构不变。
- 若手感不成立，按 ADR-0002 退化为引导式对接（提示"再近一点/角度偏左"），不延长工期。
- 真机验收由 020 承接。
