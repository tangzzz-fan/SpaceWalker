## 背景

现在的界面能用但丑：三个模块共用一张塞满小字与调试数据的顶部卡片；底部是一排 5–9 个无文字图标；满屏同一种半透明胶囊；天宫有 5 个常驻标签压着模型；三个模块靠图标互相跳，用户不知道自己在哪、还能去哪。结果是新用户 10 秒内说不出「这是看星星 + 拆飞船的」。

解法是「深空仪器」：一套统一的玻璃仪器语言（黑、冷白、一点暖金、细线、等宽只给读数）、清晰的三模块导航、把调试信息全部赶出主界面。视觉稿已由 open-design 产出并经评审裁决，本 spec 只负责把这份基准落进代码，并让「落得对不对」变成可自动断言的事。

## 用户故事

1. 作为第一次打开的用户，我想一落地就看到星空跟着手腕转，不用先点任何按钮就能明白这是观星应用。
2. 作为用户，我想在屏幕底部看到 3 个**带文字**的一级入口（星图 / 太阳系 / 天宫一号），随时知道自己在哪、还能去哪。
3. 作为用户，我想切换模块只用 1 次点击，不管当前在哪个模块。
4. 作为用户，我想顶部状态条只告诉我「在哪、现在什么状态」，不显示 fps、pick 自检、坐标系这类看不懂的串。
5. 作为单手操作的用户，我想每个模块的**唯一主操作**落在屏幕下 40%，拇指够得到。
6. 作为用户，我想主操作只有一个、且是暖金实心，不用在一排图标里猜哪个是主要动作。
7. 作为用户，我想底部上下文控件不超过 3 个、且每个都有文字，不用记图标含义。
8. 作为用户，我想次级操作收进「…」，不要占主界面。
9. 作为用户，我想看一艘不被标签挡住的天宫一号，默认态一个浮标都没有。
10. 作为用户，我想点中某个舱段时才看到**那一个**部件的标签和引线。
11. 作为用户，我想选中后从底部升起一张信息卡，读完能下滑收起，且它不遮挡主操作。
12. 作为用户，我想在信息卡里只看到与这次选择有关的动作，主操作不重复出现在卡里。
13. 作为观星用户，我想用「找星」搜到一颗星并让相机转过去高亮 3 秒。
14. 作为观星用户，我想切「今夜」对齐真实天空；拒绝定位时改为手动选城市，不反复弹权限。
15. 作为观星用户，我想用图层菜单开关连线 / 轮廓 / 星群 / 星官，不用记图标。
16. 作为太阳系用户，我想底部常驻暂停键 + 滑杆 + 速度档，拖动时看到目标天数。
17. 作为太阳系用户，我想点中一颗行星看到名称、直径、距日、周期与一句说明。
18. 作为太阳系用户，我想看到「比例为可读性做了非线性压缩」的说明，但只在卡片脚注里。
19. 作为天宫用户，我想用一条三段任务条（拆解 → 装配 → 对接）知道任务走到第几步。
20. 作为天宫用户，我想对接时在一个 HUD 里同时看到距离读数、姿态偏差、容差环、粗/精调与四类失败原因。
21. 作为天宫用户，我想剖面 / 工程图 / 再入这些模式默认关闭，打开时不改变模型外形比例。
22. 作为天宫用户，我想再入彩蛋未解锁时按钮置灰并说明解锁条件，而不是整个入口消失。
23. 作为开发者，我想调试数据只在长按版本号 3 秒后出现的诊断面板里，主界面一处都没有。
24. 作为审核者，我想所有面向用户的文案里不出现「空间站」，史实日期只用三条已核实的日期。
25. 作为戴眼镜 / 不戴眼镜的用户，我想正文对比度 ≥4.5:1、最小字号 11pt、所有触区 ≥44×44。
26. 作为在夜里使用的用户，我想深色与亮色主题都实际渲染过，不靠「应该没问题」。
27. 作为维护者，我想「3 个 tab、主操作唯一、≤3 控件、零调试文案、选中才显示」这些规则由状态断言守住，而不是靠每次截图肉眼复查。
28. 作为维护者，我想改了实现就回改设计稿、改了稿就同步实现，不出现稿一套代码一套。

## 实现决策

1. **单一结构真相**：在 `AppState` 增加 `ChromeState` 值切片（现有切片为 route / space / flags）。字段为 `route`、`primaryAction`、`contextControls`、`statusLine`、`debugOverlay`、`visibleLabels`、`infoCard`。类型 Equatable / Sendable。
2. **派生而非散落**：纯函数 `ChromeState.derive(route:selection:diagnosticsEnabled:)` 计算全部 chrome 结构；`makeAppReducer()` 在 `.route`、新增 `.select`、`.toggleDiagnostics` 时统一重算。三个主视图改为**只读渲染** ChromeState，不再用各自的 `if` 决定有没有标签、有几个控件、显不显示调试行。
3. **默认落地改星图**：`LaunchMode.initialRoute` 与 `AppState` 初始值同源，默认 `.sky`。与 3 tab 一起改，避免二次动导航。
4. **选中事件单一来源**：星图 / 太阳系 / 天宫的选中都通过 Store action 通知；标签可见性与信息卡来自 ChromeState，不再由 View body 直接读 session 的 `@State`。这是本次唯一跨 session / scene 边界的改动，需保留既有 session 行为（对接、剖面、工程图、再入）不回归。
5. **诊断开关唯一来源**：`LaunchMode` 增一个接收环境字典的纯函数，收编目前 `SPACEWALKER_TG_*`（字典注入）与 `SPACEWALKER_FLAG_*`（直接读 ProcessInfo）的不一致；主界面默认全关，长按版本号 3 秒才进入诊断面板。
6. **布局规则**：一级导航 3 项且都带文字；状态条 44pt **只读**（模块名 + 一句状态 + 「…」）；底部自上而下为唯一主操作条 → ≤3 个带文字上下文控件 → 3 个 tab；主操作落在下 40%，不重复出现在状态条或信息卡；信息卡高度 ≤ 屏高 32%，升起时停在主操作上方。
7. **标签与信息卡**：天宫部件标签默认不显示，选中只出该模块一个；信息卡只在有选中时出现，可下滑关闭。既有「剖面 / 工程图 / 再入」保持默认关闭。
8. **视觉来源**：颜色 / 字号 / 间距 / 圆角 / 描边 / 动效时长全部取自 v1.1 稿的 token 表，代码不写裸值；强调色只给主操作与当前选中项，覆盖面积 ≤10%。稿与实现同源，改一边必须回改另一边。
9. **动效与预算**：只用相机 450ms easeInOut / 面板 280ms easeOut / 状态 150ms linear 三类原语；不新增几何、粒子、后处理、发光描边；60fps 是体验目标（现实约束），数值验收判据以 PRD NFR-01 为准（A/B 平均 ≥55fps、下限 ≥30fps；C 平均 ≥25fps、下限 ≥20fps，真机 30s 录屏 + 帧率统计），允许的常驻动画仍只有轨道运动本身。
10. **平台边界**：仅 iPhone 竖屏、iOS 26+；不引入 AR / 相机、不做横屏与 iPad 版式；上架名「星槎」已落地。（2026-11-17 董事长裁决：bundle id 由 `com.tango.spacewalker` 改为 `com.tango.xingcha`，上架前零迁移成本；原「bundle id 不变」约束作废，见 `docs/design/NAME.md` §6。）

## 验收标准

- [ ] 三个模块一眼可分；一级导航恰好 3 项、都带文字、当前项有明确指示
- [ ] 状态条 44pt 只读，两行以内，主界面调试信息 0 处
- [ ] 每个模块唯一主操作，落在下 40%，不重复出现
- [ ] 底部上下文控件 ≤3 个且都带文字；次级操作进「…」
- [ ] 默认落地星图；切模块 ≤1 次点击，任意模块互达
- [ ] 天宫默认态零浮标；选中只出该模块一个标签
- [ ] 信息卡选中才升起、≤32% 屏高、可下滑关闭、不遮挡主操作
- [ ] `ChromeState` 相关单测全绿，既有 358 项测试零回归
- [ ] 深色与亮色都实际渲染过；产物里搜不到硬编码色值与非 token 间距
- [ ] 全稿「空间站」0 次；史实日期只用 2011-09-29 / 2016-03-16 / 2018-04-02
- [ ] 真机帧率复测按 PRD NFR-01 数值判据（A/B 55/30、C 25/20，30s 录屏 + 帧率统计；60fps 为体验目标），由人工门禁票 080 承接，本 spec 不自行宣告通过
- [ ] 与 v1.1 稿逐屏对照一致（14 屏），差异必须回改稿或回改实现

## 测试缝

**唯一自动断言缝**：`ChromeState` + `makeAppReducer()`，用项目已有的 `reduce` 断言通道（`AppReducerTests` 风格）。`SpaceWalkerTests` 只链接 `TGReduxKit` product，未链接 `TGReduxKitTesting`，因此不引入 `TestStore` 依赖、不产生 xcodeproj 漂移；seam 本身不变。好测试只断言外部可观察的状态派生结果，不断言私有方法、View 层级或像素。

- 先例：`AppReducerTests`（route 变更）、`SolarSystemReducerTests`（selected 派生）、`LaunchMode` 的字典注入纯函数测试、史实禁词测试。
- 覆盖：默认 `route == .sky`；3 个 tab 的文字与选中态；`primaryAction` 唯一且归属底部；`contextControls.count <= 3` 且每个都有文字；`debugOverlay` 默认全 false；`selected == nil` 时 `visibleLabels` 空且 `infoCard == nil`；选中实验舱后 `visibleLabels == [.lab]` 且 `infoCard != nil`；诊断开关纯函数；用户文案禁词与史实日期。
- **不新增** XCUITest 断言：既有 UI 测试继续做存在性断言 + 截图存档（不比对）；视觉、布局、动效、深/亮主题由截图对照与人工门禁核验。
- 068 人工门禁（5 人盲测 ≥4/5、真机帧率）单列子票承接，本 spec 不合并宣告。

## 不做什么

AR / 相机能力；横屏与 iPad 版式；多语言；新的几何、粒子、后处理或动效系统；史实内容新增或改写；后端、账号、网络；重构 TGReduxKit 包内部；改 Xcode target / 目录名（bundle id 已于 2026-11-17 经董事长裁决改为 `com.tango.xingcha`，不再属本 spec 禁区）；068 盲测本身的执行；上架素材与截图提交。
