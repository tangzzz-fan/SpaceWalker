# 047: 候选查询以方向为单位

**What to build:** 让场景能回答「朝这个方向看有什么可选中」，而不是只能回答「屏幕这个点命中了什么」。当前的点环取中心方向调用它；B 阶段的视锥选中取视锥内的若干方向调用同一个入口。触摸点选保留原路径，手感不变。

这是本轮唯一一处改结构而非搬迁的地方，也是唯一按未来形状定下来的接口：视锥没有屏幕点，若把 seam 定在坐标上，B 阶段要重做一遍。

## 实现记录

- 新增 `SkyScene.candidates(along:)`，一次返回星体、星座、星群三类候选；`pickAtCenter()` 退成一句转发。
- 命中门槛从「屏幕点距离 ≤ 22pt」换成「角距 ≤ 视场 × 22 / 屏高」。理由是视锥选中没有屏幕点，seam 只能以角度为单位；同时带来一个副作用：捏合缩放不再改变命中范围（旧实现下视场越小、同样 22pt 对应的角度越小，命中越难）。
- 行为对照：新旧两版各跑一次 `SPACEWALKER_DWELL=1` + `SPACEWALKER_AIM=Ori`，识别日志去掉时间戳后逐行一致（`sky.region Ori` → `sky.dwell Bellatrix mag=1.64 offset=3.4`）。
- 触摸点选路径未动，仍是 `pick(at:)` 的屏幕坐标判定。
