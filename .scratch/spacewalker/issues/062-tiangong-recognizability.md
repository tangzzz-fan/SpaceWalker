## 背景

仓库没有任何 3D 资产，PRD 决策 C 阶段走程序化几何。这条路线的唯一风险不是"做不出来"，
而是**做出来认不出**：圆柱加两块板，可能像航天器，也可能像路由器。

这条票是一道闸门：在往上叠拆装与对接之前，先证明"看起来是天宫一号"。
不达标就不往上叠——否则拆解、装配、对接全建在一个用户看不懂的东西上。

## 范围

- 在 015 的骨架上做三种表达，各出一组四视角截图（正视 / 侧视 / 俯视 / 斜 45°）：
  1. **实体**：圆柱 + 板 + 环，纯色材质，靠轮廓与比例
  2. **线框/骨架**：只留舱段接缝与太阳翼边框，靠结构线
  3. **剖面/示意**：一段剖开露出内部，或按三视图排布
- 用真实比例（1:20）而不是夸张比例——辨识度必须建立在正确的比例上。
- 交付结论：选一种表达作为 C 阶段基准，并写出"为什么不选另外两种"。

## 验收标准

- [x] 实体表达已出图（斜 45° 与侧俯视两版），见下。
- [x] **盲测结论：不通过**。裸看是「两段圆筒 + 两片薄板 + 一个锥」，读不出航天器。
- [x] 只做了实体表达就停：它对 1:20 的示意目标是成本最低的一种，线框/剖面只会更抽象。
- [x] 采用降级方案：**示意模型 + 常驻部件标签**，不做写实。
- [x] 全部 `MeshResource` 生成，无外部资产。

## 判定与取舍

| 表达 | 结论 |
|---|---|
| 实体（圆柱 + 板 + 锥） | 比例正确但不具辨识度；**采用**，因为它是唯一能承载「拆解/装配」的实体形态 |
| 线框/骨架 | 未做。舱体轮廓就是圆柱投影，线框只会更像管线图 |
| 剖面/示意 | 未做。剖开会破坏 FR-C-02 的「分离后悬浮」玩法 |

降级的代价与补偿：
- 代价：用户第一眼认不出「这是天宫一号」，需要读标签。
- 补偿：五个部件常驻标签（神舟飞船 / 实验舱 / 资源舱 / 太阳翼 ×2），投影位置每 0.1s 跟随相机。
  顶部同时给出「1:20 · 全长 10.4 m · 最大直径 3.35 m」与两条史实，身份由文字而非几何建立。

## 实现记录

- 标签用 `TimelineView(.periodic 0.1s)` 自刷新，**不把锚点写回 `@State`**。
  写回状态会让整个 body 每 0.1 秒重算、RealityView 跟着重算，实测会白屏。
- 标签锚点是各部件中心的屏幕投影，向上偏 24pt 避免压住几何。

## 测试缝

无自动化测试（这是外观判定）。可复用的一条：几何总量与包围盒尺寸做成断言，
保证 015 的尺度与面数预算不被这次实验破坏。
