## 技术路线调研结论

- iOS 26 起官方主推 `RealityView` + `SpatialTrackingSession`：默认会话已包含 camera/world/plane/object/image/face 追踪与 occlusion/shadow/collision/physics，`camera: .back` 提供相机背景；`run(configuration)` 返回 `unavailableCapabilities` 用于降级。
- WWDC25 新增可用交互积木：`ManipulationComponent`（免手写拖拽/缩放/旋转）、`MeshInstancesComponent`（海量实例）、`EnvironmentBlendingComponent`（现实遮挡）、`ARKitAnchorComponent`（直取 ARKit transform）。
- 兼容备选为 `ARView` + ARKit（资料多、可下探 iOS 18，但手势/锚点要自己写，且用不上新 API）。
- 边界：AR 能力**无法在模拟器验证**，编译通过不等于真机可用；真机需 iPhone（用户设备 iOS 26.6 满足最低要求）。

## 姿态跟随修复：方向错 + 抖（真机确认解决）

- 症状：转头方向相反、星空剧烈抖动、不跟随。
- 根因 1（方向）：CoreMotion 参考系 Z 朝上、RealityKit 世界 Y 朝上，原实现用 `(x, z, y)` 分量交换 —— 这是**反射矩阵**（det=-1），水平镜像。正确换基是 `(x, z, -y)`，等价绕 X 轴 −90° 纯旋转。
- 根因 2（抖）：姿态被拆成 `yaw=atan2(x,-z)` + pitch，接近天顶时 1/cos(pitch) 发散；且 30Hz 定时器 → `@State` → SwiftUI body → `RealityView.update` 写实体，与 60Hz 渲染不同步。
- 修法：完整四元数（含 roll）直驱 `root.orientation=inverse(deviceToWorld)`；67Hz 运动回调内直写实体，不经 SwiftUI；20ms 球面平滑；用 `motion.gravity` 运行时校验四元数约定（两候选取满足 R·g=(0,-1,0) 者），日志只判定一次未翻转。
- 顺手修复：`pick` 一直用**局部坐标**投影，根节点旋转后点击全错；改 `root.convert(position:to:nil)`。
- 真机证据：rate 66–67Hz，`fwd` 从 (0,-1,0) 平滑扫到 (0.61,-0.36,-0.70)，人工确认跟手不抖。
- 删除 `SkyRig.aim`（拆 yaw/pitch 的旧路径，无生产调用点），仿真器降级只留 drag。

## M2-024 今夜此刻（FR-B-05）

- **前置缺陷**：`StarField.direction` 用 `(x,z,y)` 轴交换，等价对物理右手系做一次反射（`RA0 × 北极` 应为 `-RA6h`，原实现给 `+RA6h`）。单星无感，但对齐真实天空会得到镜像星座，且反射无法用四元数表示。修法：`z = -cosδ·sinα`，加"基向量叉积 = -1"单测。
- `Astronomy`：JD → GMST（280.46061837 + 360.98564736629·d）→ LST（+经度）；赤道→地平用标准时角公式；再用地平单位向量拼出旋转矩阵的三列（RA0 / 北极 / RA18h，注意第三个基向量是 **RA18h** 而非 6h，因为修手性后 data z = -RA6h）。
- `SkyObserver`：`CLLocationManager` 请求 when-in-use + `startUpdatingHeading`；航向只取一次（`headingAccuracy ≤ 25°`），offset = `trueHeading − sceneAzimuth(设备前向在任意帧的方位)`，会话内保持。
- 场景结构：`root`（姿态，每帧直写）→ `field`（地平旋转 + 航向偏移，1s 节流）→ 6 个星桶网格。两层互不干扰，拾取走 `root.convert(...to:nil)` 自动包含两层。
- 未授权定位：field 仍应用地平旋转（高度正确、方位未校准），顶部/卡片明确标注，不阻塞主流程。
- 验证：单测 156 项 0 失败；模拟器（定位=北京、`simctl privacy grant location`）`sky.align location=39.904,116.407 sidereal=321.4`，对齐状态下 pickProbe 仍 288/288（证明 root×field 复合变换与拾取一致）。
- 调试开关：`SPACEWALKER_ALIGN=1` 启动即开启对齐。
- 待人工：真机北极星高度 38.9–40.9°、拒绝权限后仍可用、星座形状不随会话朝向变化。
- 坑：真机 USB 隧道会掉（`CoreDeviceError 4`），此时 `-destination id=` 构建会超时；改用 `-destination 'generic/platform=iOS'` 构建，再单独 install。

## 024 追加：拾取空间 bug、可选/背景视觉区分、按星校准

- **拾取空间 bug（真机暴露）**：`field`（地平旋转）是 024 新加的中间节点，星点成了它的子节点，但 `project` 仍用 `root.convert(局部坐标)`、角距预筛用世界坐标方向比赤道坐标星表方向 —— 两处都漏了 field。现象：准星里明明有星（18.6pt、可选中）却 pick 不出。修法：`field.convert(...to:nil)` + `viewDirectionInField = (root*yaw*field)^-1 * -z`。教训：**往返探针会跟着错误实现一起自洽**，探针必须按"渲染真实位置"构造才有意义。

## M2-025 星座连线 + 找星直达 + 校准按钮坐标系修复

- **真 bug：按星校准按钮恒不可点**。`aimOffset` 拿「星的世界方向」和 `deviceForwardWorld` 比夹角 —— 后者是设备前向在**世界坐标**的方向（世界 y 是屏幕上方，随姿态转），而星在准星中心时世界方向恒为 (0,0,-1)。两者不是同一参考系，夹角几乎总 > 3°。
  修法：与 `screenCenterDirection = (0,0,-1)` 比较。纯函数 `SkyPicker.offsetDegrees` 单测锁 0/90/180。
- **同类错误第二处**：`sceneAzimuth` 三处调用都用 `deviceForwardWorld`（世界坐标），应改用 `viewDirectionInField`（地平坐标）。
  推导：`offset_new = targetAz − sceneAz`，其中 sceneAz 含旧 offset K；星与设备在 field 中各减 K，K 抵消 → 公式自洽，不需要回退旧值。
- **星座连线**：31 星座 / 138 连线 / 154 颗专名星。线段用 4 面细柱（双面写，防背面剔除），合并单 mesh，radius 0.032。数据靠「引用名必须存在于星表」单测兜住拼写错误。
- **找星**：中文星名 127 条（传统星官名，其中天关/玄戈/天一/傅说 4 颗为 IAU 2017 正式名）、88 星座中文名、俗称（北斗→UMa、北极星→Polaris 等）、四路检索；指路用 `yaw/pitch` 相对角度 + 箭头，3° 内自动选中。
- 顶部计数「0 颗可选中」的原因：`scene` 不是 @Observable，`nodes` 填好后视图不刷新。改成从 `catalog.stars` 过滤，纯派生自 @State。
- 底部栏按钮增多会换行：把「对齐今夜」缩成「今夜」、「太阳系」改纯图标。
- 174 项单测 0 失败。真机安装成功但设备锁屏无法启动（FBSOpenApplicationErrorDomain 7），待解锁验证。
