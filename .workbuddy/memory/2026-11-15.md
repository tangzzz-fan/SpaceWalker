### 本轮查出的实质问题（重要）

1. **门禁项 3 判据写错**：清单/票 080 原写「iPhone 16 / iOS 26.6、60 秒平均 ≥60fps」。PRD NFR-01 实为 **A/B 平均 ≥55fps、下限 ≥30fps；C ≥25/20；基准 iPhone 16 Pro / iOS 26.6；30s 录屏 + 帧率统计**；票 068 另要 C 阶段 70 秒排除启动 5 秒。「60fps 硬指标」出自 UI PRD v1 §0 现实约束与 074 动效预算，不是数值判据。已按 tracker 约定「issue 与 PRD 冲突以 PRD 为准并回写 issue」修正清单与票 080；074 spec / UI PRD / 079-diff 里的旧措辞**故意没改，留待人裁决**。
2. **068 欠账映射漏项**：080 把 068 的 X-07「不看标签认出天宫一号 ≥4/5」/ X-08 细节评分 ≥3，与 UI PRD 的「10 秒说清看星星+拆飞船」定位盲测混为一谈。若 080 五项过了就关 074，068 的辨识度盲测仍未结，而 PRD §11.2 写明「M3.1 不过，不进 1.0 内容冻结」。已在清单/票里标为待董事长裁决（纳入 080 / 另开票 / 豁免）。
3. **`tools/device.sh` 用法坑**：`log` 只收 `--interval/--once/--grep`，**不接受文件名**（原清单命令直接报「未知参数」），输出走 stdout 要重定向；`shot` 参数是完整路径要带 `.png`；`resolve_udid` 偶发解析不到有线设备，显式 `export SPACEWALKER_UDID=...` 绕过。这些是文档错误，脚本本身未改（无授权改代码）。
4. **旧真机包陷阱**：`build/Build/Products/Debug-iphoneos/SpaceWalker.app` 停在 11/08，早于 075–079 全部改动；取证前必须重编 `xcodebuild -destination 'generic/platform=iOS' -derivedDataPath build build`。
5. **`devicectl process launch` 对已运行进程只是重新激活**，环境变量不生效（第一次切天宫失败，日志仍打 `sky.region`）。必须 `device info processes` 取真实 PID → `process terminate --pid` → 再 `launch --environment-variables`。
6. **`FrameRateSampler(window: 120)` 是滚动 120 帧窗口**：`sky.perf` 5 秒一行、`tiangong.fps` 2 秒一行，`avg` 是最近约 2 秒、`min` 是该窗口最慢单帧。日志**不能单独充当 NFR-01 的 30s 帧率统计**，正式统计仍需录屏/Instruments。
7. **076「`LaunchMode.environment()` 是唯一读取 ProcessInfo 的入口」不字面成立**：HEAD 仍有 48 处（075 时 47，非本批回归），2 处直接下标绕过 helper（`DeviceAttitude.swift:11` MOTIONLOG、`SpaceView.swift:290` SELECT）。措辞需收敛，但不影响门禁项 5 的「TG_* 行为不变」判定。
